End-to-End Soundness of a Context-Sensitive
Goblint-Style Analyzer in Isabelle/HOL
Manuel Lerchner #
Technical University of Munich, Germany

      Abstract
Goblint-style abstract interpreters translate a program into side-effecting equations, with one
unknown per program point and calling context, and solve them with a generic solver. The partial
correctness of that solver has been verified in Isabelle/HOL, but the theorem does not connect the
equations to the program. We mechanize this connection for a small imperative language with
recursive procedures. We adapt the local traces of Schwarz et al. to procedure activations, because
a return must resume exactly the activation that made the call. A context policy relates each
activation trace to the calling contexts it may belong to. The development provides (i) a coverage
contract of five local obligations over an arbitrary control-flow graph, which bounds every valid trace
in every admitted context; (ii) a proof that every post-solution of the generated, context-routed
equations meets the contract, using the verified solver only through its certificate; and (iii) an
end-to-end theorem from a small-step source semantics to the verdicts of the analyzer function that
Isabelle exports to OCaml, for every configuration it offers. The guarantee is per program point:
every reached store is covered by the report and satisfies its definite verdicts. It is partial correctness,
since solver termination is not proved, and the language has no pointers or heap.

 1      Introduction
A context-sensitive static analyzer keeps a separate abstract state for each program point
and calling context. In the program of Figure 1, main calls bump(5) and bump(4), and bump
returns its argument plus one. An interval analysis with one state per program point must
describe both calls at the return of bump. It therefore cannot prove either check. With
contexts that record the argument, it analyzes bump once per argument and proves both.
Goblint, an abstract interpreter for C [35, 30], gains this precision by translating a program
into a side-effecting constraint system [29, 1]. This is a system of inequations over unknowns
indexed by program point and context, whose right-hand sides may also contribute to other
unknowns. A generic top-down solver then solves the system.
    That solver has been verified. Stade et al. proved it partially correct in Isabelle/HOL [32],
and Tilscher et al. extended the proof to side effects [33]. When the solver terminates, it
returns a post-solution on the unknowns it solved, a set closed under the reads of right-hand

      gap needs a concrete semantics in which a per-context state has something to cover. Such
      semantics are classical on paper. Sharir and Pnueli distinguish the call-string and functional
      approaches [31]. Jeannet and Serwe derive interprocedural analyses by abstracting a stack
      semantics [13], and Van Horn and Might derive sound analyses from abstract machines
      by bounding their stores [11]. What has not been mechanized, to our knowledge, is the
      connection from a source semantics through such a context-indexed semantics to a side-
      effecting constraint system and its verified solver.
          We mechanize this connection. The development, Voblint, is written in Isabelle/HOL
      and contains no sorry. Its parts are the following.
          We adapt the local traces of Schwarz et al. [27] to procedure activations. An activation
          trace records one activation and the activation that created it. A context policy, which
          may admit several contexts for one call, relates traces to contexts. We prove that five
          local obligations on a cover bound every valid trace in every admitted context, over an
          arbitrary control-flow graph (Section 3).
          We prove that every post-solution of the generated, context-routed equations meets these
          obligations, provided the context policy agrees with the routing of the equations. The
          verified solver enters only through its certificate (Section 4).
          We prove an end-to-end theorem about the analyzer function that Isabelle exports to
          OCaml. Whenever it returns a report, every store that a finite source execution from
          an initial store reaches is covered by the report at the corresponding program point and
          satisfies every definite verdict there. This holds for every configuration the function offers
          (Section 5).
          We show that the theorem is not vacuous, that a domain obligation rejects a real Goblint
          defect, and how calling contexts change verdicts on recursive programs (Section 7).
      The solver, side-effecting constraint systems, local traces, and Goblint’s split between analyses
      and solvers are prior work. The context-indexed semantics is the structure of our proof. The
      shipped guarantee is per program point. It is not a separate certificate for each context’s
      row of the report (Section 5).
          The scope is limited. The source language, VIMP, has integer variables, global variables,
      and recursive procedures with parameters and return values, but no pointers, arrays, or heap.
      The result is partial correctness: the analyzer answers only when its solver run terminates,
      and termination is not proved for every program. The parser, Isabelle’s code generator, the
      OCaml toolchain, and a solver-tracing hook are trusted.

       3      Activation Traces and the Coverage Contract
      This section has three ingredients. Valid activation traces are adapted from the local traces
      of Schwarz et al. [27]. Context policies generalize the call-string and functional choices of
      Sharir and Pnueli [31] to a relation. The coverage contract and its soundness theorem are
      ours. Nothing here mentions an abstract domain, an equation, or a solver.
          A context-sensitive analysis claims, for each node v and context c, a set of stores. Checking
      such a claim needs the stores that executions bring to v in context c. A graph execution
      with a frame stack does not provide them. A frame holds only what is needed to resume the
      caller and disappears at the return, and the list of visited node–store pairs interleaves the
      steps of all activations. Grouping a run by activation makes the missing structure explicit:
      each call starts an activation attached to its caller, and each return composes the finished
      callee back into that caller.

      3.1     Activation traces
      An activation path is the list of node–store pairs visited by one activation. An activation trace
      has one constructor for each way an activation begins or continues (activation_trace):
      datatype activation_trace =
         Root activation_path
       | Call (activation_trace_caller: activation_trace) activation_path
       | Resume (activation_trace_current: activation_trace) (activation_trace_callee: activation_trace)
         activation_path

      That is, Root π is the activation of main, Call t′ π is a callee whose creator t′ is frozen at the
      call site, and Resume t′ t′′ π continues t′ past the call that produced the finished callee t′′ .
      The observers sink_node t and sink_store t return the last node and store of the path, and
      caller_of t the creating caller, which a Root lacks.

3.2    Calling contexts as a relation

An analysis chooses a callee’s context at the call: with call strings of length k, the last k
call sites; with entry-state contexts, the abstract values of the formals at entry. A context
policy fixes this choice for every concrete call. It maps a call site u, a caller context c, a
description of the call, the caller’s store, and the entered store to the set of admitted callee
contexts (context_policy). The result is a set because Goblint’s enter may return several
alternatives for one call, each routed separately. When the alternatives overlap, one concrete
call is admitted in several contexts (ov_two_contexts_admitted). The set may be empty,
for instance at a call the analysis considers unreachable.
    For a call edge e into p, we write adm u,c (e, s, s′ ) for the set the policy returns for the
call described by e and p, caller store s and entered store s′ . We write c′ ∈ adm ∃u,c (p, s, s′ )
when some call edge from u into p has entered store s′ from s and the policy admits c′
for it (admits_call_context). The contexts a trace carries are then defined inductively
(activation_context_rel):

                                  t′ carries c
    Root π carries c0        Resume t′ t′′ π carries c
    t carries c c′ ∈ adm ∃sink_node t, c (p, sink_store t, s′ )
         Call t ((FunctionEntry p, s′ ) # π) carries c′

That is, a callee carries every context admitted for its call from some context of its caller,
and a resumed activation keeps the contexts it had before the call. Traces store no context,
so the policy is a parameter of every theorem below. The activation collecting semantics
collects the final stores of the valid traces that end at v and carry c (activation_collect):


   AG,adm,c0 ,g,S (v, c) = { sink_store t | t ∈ TG,g,S , sink_node t = v, t carries c }.


In the running example, the final store of bump(5) lies in A(FunctionResult bump, [5, 5]) and
that of bump(4) in A(FunctionResult bump, [4, 4]), whereas C at that node contains both.

      the resumed caller still carries its contexts there. Without Total, a cover that meets the
      other four obligations can miss a reached store (total_dropped_unsound). Total asks only
      about covered stores, because an entry-state policy admits no context for stores the analysis
      has excluded. Call strings and the unit policy, which admits one context for every activation,

       4      From Equations to a Cover
      The contract of Section 3 asks for a cover. This section constructs one from a solved equation
      system. The ingredients have different origins. The analysis interface mirrors Goblint’s
      Spec [35, 30]. Side-effecting equations come from Seidl et al. and Apinis et al. [29, 1]. The
      solver and its certificate are those of Tilscher et al. [33]. The routing conditions, which
      connect the equations to the context policy, and their discharge for each policy are ours.

4.1    What an analysis supplies
An analysis describes the stores at a node by an abstract state d. Its meaning γ(d, ρ) also
depends on ρ, the solved values of the analysis’s global unknowns. We suppress ρ when it
plays no role. The analysis supplies the record dg_spec, the counterpart of Goblint’s Spec:
one transfer per kind of edge action, an enter operation, and two combine operations. A
call needs two states. After the return, the caller’s locals come from before the call, while
the globals and the result come from the callee. Enter therefore returns a list of entry pairs
(q, e): a resume state q that describes the caller’s store, and an entry state e that describes
the store in which the callee starts. Combine builds the state after the call from q and the
callee’s exit state.
     The local soundness laws form the locale analysis_contract. The concretization is
monotone, every transfer loses no successor store, and combine covers combine e (s, t) whenever
q covers s and the exit state covers t. In addition, enter must return a pair that covers the
caller’s store and the entered store (entry_pairs_cover). A numeric domain proves only
its abstract operations sound. The framework derives the transfers once for all domains,
following Nipkow and Klein’s generic interpreter [23, Sect. 13.5]. The shipped domains are
Sign, Interval, Parity, Congruence, and their reduced product.

4.2    Context-indexed equations and routing
For every node v and context c there is a local unknown (v, c). Its right-hand side joins four
sources (routed_node_rhs_parts):
    the initial state at the program entry;
    the transfer along each intraprocedural edge into v, in the same context c;
    the combined result of each call returning to v;
    at a procedure entry, the entry states published to it.
At a call, a routing function chooses the callee context from the call site, the caller context,
and the entry state. Each call publishes its entry state as a side effect to a global seed
unknown for the callee and the chosen context, which the callee’s entry equation reads. A
recursive call needs no special treatment: its equation reads an exit state that depends on
the caller’s own unknowns, and the solver handles the cycle as it handles a loop.
    The equations choose a callee context from an abstract state, while the concrete semantics
chooses one from the concrete call through the policy adm. Two conditions make the choices
agree. Both are assumptions of the locale routed_context.
Adequacy (routing_adequate). If adm admits c′ for a call from a store that the caller’s
    solved state describes, then enter produces a pair (q, e) that is routed to c′ , whose resume
    state covers the caller’s store and whose entry state covers the entered store. The callee’s
    entry unknown in c′ is solved.
Totality (routing_total). adm admits at least one context for every call from a store that
    the caller’s solved state describes.
For the unit policy and for call strings, adm admits exactly the context the routing function
computes from the call site and the caller context. Totality is then immediate, and adequacy
reduces to entry coverage and the routed entry unknown being solved.
    For entry-state contexts, the policy routed_entry_context_rel is defined from the
solved valuation σ:

   adm u,c (e, s, s′ ) = { route(u, c, e′ ) |
                                                (q, e′ ) ∈ enter(σ(u, c)), s ∈ γ(q), s′ ∈ γ(e′ ) }.

Here σ(Inl u) is the value of a local unknown u; global unknowns are the Inr side of the
sum. That is, the query is solved, V is closed under the reads of right-hand sides, and σ
bounds both the right-hand side and every side effect of each solved unknown. The two
certificates point in different directions. The solver works backward from its query, the result
of main, while Theorem 2 follows executions forward from the entry. The bridge restricts
V to its live part: the unknowns (u, c) such that u belongs to a procedure q whose result
(FunctionResult q, c) is solved (live_unknowns). The compiler ends every body with a return
edge, so every node of a procedure reaches the procedure’s result through intraprocedural
edges and call-to-continuation steps. Closure under reads then puts all nodes of a procedure
into V once its result is solved in that context. live_unknowns_cover proves, from a
well-formed program and a returned solve, that the live set contains the program entry and
is closed forward. This is structural reachability in the graph. It does not claim that an
execution reaches the result. Three sets are involved: the solver’s solved set V , its live subset,
on which Theorem 2 is applied, and the states the report publishes, which are taken from V .
Publishing more states than the proof uses is sound, because the report only has to contain
the cover.
    The rest of the proof never inspects the solver. The analysis locale takes the solver as a
parameter and assumes four facts about it (certified_solver): a run in its domain yields
part_post_solution and a finite solved set, and a run of its executable form that returns
lies in the domain and agrees with the logical solver. These facts are proved for the vendored
solver under each of its five update rules for global unknowns (td_certified_solver). An
update rule decides how contributions to a global unknown accumulate: by join, by join per
contributing right-hand side, or by warrowing, which combines widening and narrowing [33].
Replacing the solver would not touch the semantic layer.

 5      The End-to-End Theorem
The previous sections bound the activation collecting semantics of a graph. Two links remain:
from source executions to graph executions, and from the solved valuation to the report the
user reads. The forward simulation follows the CompCert methodology [18]. The elaboration
that locates a source configuration at graph nodes, and the composition, are ours.

From source to graph. VIMP has a small-step semantics pstep over configurations of
a residual command, a store, and a frame stack. The compiler translates each procedure
body by continuations into a procedure-aware CFG, and a forward simulation matches every
source step by graph steps that reach the same store (csim_star). A source configuration
does not determine a graph node, since its residual command can occur at several places, as
in if (b) {x = 1;} else {x = 1;}. The run is therefore lifted to an elaborated program
whose annotated commands name their nodes, and the relation p, s0 ⊢ cfg ▷ v (at_node)
observes a configuration at the nodes of its lifted runs. It is a relation, and the theorem below
quantifies over every node at which a configuration is observed. Combined with Section 3,
every store a finite source execution reaches lies in C at a node the simulation relates to
the run (source_reaches_node_collect), and on the elaboration this holds at every node
where the run is observed (csim_point_compile_prog).

       and a returned report. The conclusion has two halves: the reached configuration is observed
       at some node, and at every node where it is observed, its store is collected, covered by the

       proof, through C(v) = c A(v, c) and Theorem 2. The guarantee is therefore per program

       state for c, but the report is not proved to list that state as the row for c. Closing this gap is
       future work (Section 9).

       no termination premise: run_voblint answers only when its executable solve returns, and a
       returned run lies in the solver’s domain. It has no coverage premise: live_unknowns_cover

       no well-formedness premise: a malformed program does not yield Analysed. The statement
       holds for every analysis configuration the function accepts, because the configuration is a
       quantified argument.

the execution, so a verdict for one check does not depend on an earlier one. The locals of main
start unconstrained, while a callee’s locals start at 0. min, max, and the nondeterministic
input are built-in calls. A verdict therefore need not hold for a C program with the same

 7     Evaluation
A machine-checked theorem can hold for uninteresting reasons. Its premises may never
hold together, its obligations may exclude no error a real analyzer makes, and an analyzer
that answers UNKNOWN everywhere satisfies it as well (unknown_everywhere_sound). We
therefore check that the premises can hold and that the obligations have force, and then
measure what contexts and domains buy on concrete programs. Each item states its kind of
evidence. Facts about one fixed program are proved by eval, which runs generated code and
therefore also trusts the code generator. Analyzer outputs are registered claims that pixi
run thesis-claims re-checks against the analyzer, and the paper’s tables are generated
from them.

The theorem is not vacuous (machine-checked, one program each). For the program
of Figure 1, analyzed with Interval, entry-state contexts, and the warrowing update rule,
a theory builds a source execution that returns from both calls. Evaluation shows that
the analyzer answers with both checks PROVED, and nv_source_certified instantiates
Theorem 3 with every premise discharged. Companion instances do the same for a single
check (nv_check_proved_sound) and for a DEAD check (nv_dead_unreached). These show
that the premises are satisfiable. They do not measure how often the analyzer answers.

The obligations have force (machine-checked). Total is needed: total_dropped_
unsound exhibits a cover that meets the other four obligations and misses a reached store. At
the domain level, Goblint once claimed c % 2 == 1 for c ∈ {−5, −7}, although C’s truncating
remainder gives −1 (issue 1156, fixed in [26]). This defect involves no contexts. It violates a
domain law. In Voblint, the congruence domain’s remainder must satisfy congruence_mod_
sound, an assumption of the locale through which the domain is registered. The law requires
the truncating remainder of any two concrete values to lie in the concretization of the abstract
result. prefix_congruence_mod_unsound proves that every abstract remainder returning
the constant 1 for (1 + 2Z) mod 2 violates it at −5. The defective operator therefore cannot
discharge the obligation.

Contexts decide checks on recursive programs (executable). Table 3 runs one regression
program under every context policy. Mutually recursive procedures f and g return 2 and
1 at the bottom of the recursion. main calls f(2) and g(2) inside a loop of 200 iterations
and checks both results. Each call chain is three call sites deep. With one context per
procedure, or with call strings of length 1, the activations of different depths share a state
and both results widen to [1, 12]. With call strings of length 2 or with entry-state contexts,

That theorem compares two solutions computed by eval. It concerns neither run_voblint
nor call strings in general.

        8     Related Work
       Concrete semantics of calling contexts. How information about a call reaches the callee
       and returns to the caller is a classical question. Sharir and Pnueli distinguish the functional
       approach, which computes input–output relations of procedures, from the call-string approach,
       which tags information with the history of calls [31]. Voblint’s call-string policy follows the
       second, and its entry-state policy, which indexes a callee’s exit states by its entry state,
       resembles a functional approach tabulated per input. The return combines the caller’s state
       before the call with the callee’s exit state, the shape of the return function of Knoop and
       Steffen [15, §4.1]. Reps et al. solve such problems precisely when facts are finite and transfer
       functions distributive [24]. Voblint requires neither and proves no precision result. Jeannet
       and Serwe derive interprocedural analyses by abstract interpretation of a standard stack-
       based operational semantics and combine the call-string and functional approaches [13]. Van
       Horn and Might derive sound analyses from abstract machines by bounding their stores [11].
       These works give contexts a concrete counterpart on paper. Voblint mechanizes one such
       counterpart and connects it to equations and a verified solver. Might and Manolios introduce
       a posteriori soundness, whose abstraction maps are constructed after the analysis has run [20].
       Voblint’s entry-state policy is similar in spirit: the abstraction is fixed in advance, but the
       relation between traces and contexts is read off the solution (Section 4).

       Verified analyzers. Verasco is a Coq-verified analyzer for most of C99, excluding recursion
       and dynamic allocation [14]. Its interpreter iterates over the structure of C#minor, reanalyzes
       a function at every call site, and raises an alarm at a possible recursive call. The value analysis
M. Lerchner                                                                                            1:15


of Blazy et al. checks the candidate of an untrusted iterator with a verified checker [3]; Voblint
instead runs a solver whose partial correctness is proved. Nipkow and Klein develop abstract
interpretation for IMP in Isabelle/HOL [22, 23], and Voblint’s non-relational domains follow
their generic interpreter. Their language has no procedures. Franceschino et al. verify an
IMP analyzer in F* that runs in a browser [8], and Cachera and Pichardie extract a certified
denotational interpreter [5]; neither has procedures. Michelland et al. make soundness proofs
reusable by sharing one interpreter between the concrete and the abstract semantics [19].
Cachera et al. compute a context-insensitive dataflow analysis with a verified solver for
ordinary inequations [4].

Contexts in mechanized semantics. Dabrowski and Pichardie instrument a concrete
semantics with contexts through a module type whose call-context function computes a
callee’s context, and prove a context-sensitive points-to analysis sound in Coq [6]. This is
the closest precedent for Voblint’s context-indexed semantics. Their analysis is specified
by constraints that no solver computes. Voblint’s contexts are admitted by a relation, the
totality condition makes the indexed collection exhaustive, and the indexing is connected to
an executable verified solver. Trace partitioning indexes sets of traces by control history [25];
Rival and Mauborgne allow coverings in which one trace has several indices and present
calling contexts as one such indexing. The activation collecting semantics is a covering
of this relational kind. Among Isabelle developments, interprocedural analyses have been
verified [16, 36], but none of these entries claims an extracted analyzer or represents an
activation with its caller chain.

Verified solvers. Hofmann et al. verify a local generic solver in Coq [10], and de Vilhena
et al. verify one that discovers dependencies dynamically in Iris [7]. Stade et al. prove the
top-down solver partially correct in Isabelle/HOL [32], and Tilscher et al. extend it to side
effects with a generic interface for update rules [33]. Voblint vendors the latter and connects
its certificate to programs. Termination is proved for top-down solvers without side effects
over a finite type of unknowns [34]. Voblint’s unknowns pair nodes with contexts. Each
program’s graph is finite, but the node type is not, and entry-state contexts need not be
finitely many, so that result does not apply.

Goblint and local traces. Side-effecting constraint systems [29, 1] and the split between
analyses and solvers are Goblint’s architecture [35, 30], and Voblint’s dg_spec follows its
Spec interface. The correspondence is architectural; no theorem transfers to Goblint’s OCaml
implementation. Schwarz et al. prove Goblint’s thread-modular analyses sound against local
traces on paper [27, 28]. Activation traces adapt their construction to procedure activations.
Activations do not interfere, so no concurrency result of that work transfers.

Differences from prior work. Voblint inherits its solver, the side-effecting constraint systems,
the analysis interface, the shape of its traces, and the distinction between call-string and
functional contexts. What it adds is their mechanized connection, from a small-step source
semantics through a context-indexed collecting semantics to a side-effecting equation system
and its verified solver, ending in a theorem about the exported analyzer. We know of no prior
mechanization of this connection. The closest, Dabrowski and Pichardie [6], has contexts in
the semantics but no solver. Verasco [14] has an executable analyzer for a far larger language.
It reanalyzes a function at each call site, raises an alarm at a possible recursive call, and
computes its result by structural iteration rather than with a generic solver.

        9     Conclusion

       We have mechanized the connection between a source semantics and a Goblint-style, context-
       sensitive, side-effecting equation system solved by a verified solver, with activation traces as
       the concrete counterpart of contexts. This is a first step, and its coverage is modest. The
       result is partial correctness. VIMP is scalar, and the adequacy of its semantics is argued,
       not proved. No general precision ordering or completeness property is proved. The precision
       results are witnesses for single programs. The guarantee is per program point.


       Per-context certification. Theorem 2 bounds each context’s collected stores by the solved
       state of that context, but the report-level theorem keeps only the union over contexts. A
       theorem stating that the report’s row for a context covers A(v, c) would make the per-context
       states a certified output.


       Memory and the caller-locals assumption. The solver certificate is stated over unknowns
       and right-hand sides, and the coverage contract refers to the language only through a few
       step functions. Features that change only these step functions, such as machine integers,
       leave the contract and its composition intact. The trace semantics, however, assumes that a
       callee cannot modify its caller’s locals, so a return can resume the caller with the locals it
       had before the call. Pointers into the caller’s frame, a shared heap, or threads break this
       assumption and would require extending the trace semantics itself.


       Termination. Solver termination is a per-program fact, established by running the solver.
       Known termination results for top-down solvers assume finitely many unknowns [34]. Entry-
       state contexts need not be finite, so a general result would need a bound on the contexts a
       solve creates.


       Data availability. The Isabelle/HOL development, the regression corpus, and the scripts
       that regenerate every analyzer output in this paper are public on GitHub and archived on
       Zenodo [17]. The archived version predates the context-policy claims and the profiling data
       used here, and a new archive will accompany the final version. The vendored solver [33] is
       not yet public, so the theories cannot yet be built from public sources alone.
