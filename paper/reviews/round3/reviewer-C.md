## Major weaknesses

1. **Theorem 2's hypothesis table understates the essential side-effect obligation and blurs the ownership of entry coverage.** Section 4.2, Table 1, p. 1:8 (`paper/sections/equations.tex:97–98`) describes `post_bounded` as “σ bounds every right-hand side on the solved set V” and `analysis_contract` as “transfers, enter and combine are sound.” The first reading must explicitly include side effects: `vendor/td-verification/Basics_side.thy:622` defines `post_bounded` using `tree_covered_at`, whose definition at lines 588–591 requires **both** `traverse_rhs t σ ≤ σ (Inl u)` and `sides_of_rhs t σ ≤ σ`. The latter is used directly in the routed combine proof (`src/Abstract_Interpreter/Framework/Context/Routed_Context.thy:534–547`). A valuation bounding only returned local values does not supply that argument. The second reading misstates the locale boundary: `src/Abstract_Interpreter/Framework/Spec/DG_Spec_Sound.thy:337–351` lists `spec_wf`, `gammaDG_mono`, `step_sound`, and `combine_sound`; it contains no enter-coverage assumption. Routed entry witnesses instead occur in `Routed_Context.thy:86–103`, with existence ensured using the routing conditions and instance-specific entry coverage. Section 4.3 correctly displays the stronger solver certificate, so this is an exposition inconsistency rather than evidence of a false theorem. Revise the table and Section 4.1 to state where each law belongs, and show the local-plus-side-effect bound in one equation. Also label the table a summary: the inherited locale has strategy well-formedness and reader-consistency assumptions (`DG_Ctx_Activation.thy:43–54`) and `routed_context` includes `is_bot bot` (`Routed_Context.thy:77`). The displayed definition of `cover` reasonably specializes away reader consistency, but the caption currently claims the table lists “the assumptions.”

## Minor comments

1. **Restore the call argument in the displayed entry-state policy.** Section 4.2, p. 1:7 (`paper/sections/equations.tex:74–76`) writes `enter(σ(u,c))` and `route(u,c,e′)`, although the left side depends on call descriptor `e`. The source definition reads `(cont,entry) ∈ set (alts ci (dg_local (sigma (Inl (u,ctx)))))` and `ctx′ = route u ctx entry (CallEdge (ci_dst ci) (ci_formals ci) (ci_args ci))` (`src/Abstract_Interpreter/Framework/Context/Routed_Context.thy:708–713`). Write `enter_e` and `route_e`, or explicitly say the edge parameter is suppressed. The current equation otherwise appears to lose the formals and arguments that determine entry coverage. This does not invalidate the source definition.

2. **Separate Boolean denotation from an evaluation-order claim.** Section 5, p. 1:11 (`paper/sections/theorem.tex:107–108`) says “Both operands of && and || are evaluated.” The inspected reference is a total, pure evaluator: `aval (And b1 b2) s = (if truthy (aval b1 s) ∧ truthy (aval b2 s) then 1 else 0)`, with the analogous disjunction (`src/Program_Model/VIMP/VIMP_Expr.thy:119–120`). These equations specify values, not an operational evaluation order. Together with total division (`VIMP_Expr.thy:19–24`), they also remove the usual observable difference for pure expressions. Clarify whether this sentence describes conservative diagnostic traversal or generated evaluation. The latter's order is **UNVERIFIED** here. Prefer a direct statement that expressions are pure and total and that the formal model does not encode C's short-circuit undefined-behavior boundary.

3. **Mark the option erasure in the handwritten return rule.** Section 3.1, p. 1:4 (`paper/sections/traces.tex:44`) writes `caller_of t″ = t′`; the source requires `caller_of callee = Some caller` (`src/Program_Model/CFG/Collecting/Activation_Trace_Def.thy:120–125`). The prose already says roots lack a creator, so the intended mathematics is clear. One sentence saying the display suppresses `Some`, or retaining it in the rule, would make the source mapping exact.
