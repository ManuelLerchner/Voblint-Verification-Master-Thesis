# Summary

I reviewed the frozen 19-page submission (SHA-256 `56755f5ab29d58880315c945115e010815a038b3a7f53154cb825ab5c485a7d0`) against the local source and executable, and independently inspected the public archive. The local artifact supports the paper's concrete analyzer results and its carefully scoped soundness story. The principal problem is distribution: the cited archive omits the necessary modified solver, whose configured public repository returns HTTP 404, and does not contain the paper's current reproduction machinery. This was source inspection and executable reproduction, not an independent full Isabelle build. I did not read other reviews or earlier submissions. No project sources were edited.

## Recommendation / Confidence 1–5

**Major revision; confidence 4/5.** This recommendation concerns artifact availability and reproducibility, not a discovered counterexample to the soundness theorem.

Badge assessment:

- **Available:** the main project and a persistent Zenodo ZIP are public, but I would withhold the badge for the complete claimed artifact until the required solver dependency is publicly obtainable and archived.
- **Functional:** the prepared local checkout passes the tested functions; the public distribution cannot presently support an equivalent clean reproduction. Withhold pending repair and a clean-checkout build.
- **Reusable:** promising modular formal interfaces and reproducible claims, but withhold pending a complete pinned distribution and short paper-specific reproduction instructions.

## Major weaknesses

1. **The public artifact omits a required, apparently unavailable dependency.** Location: p. 1 Supplementary Material and §6, pp. 11–12, where the imported modified solver is part of the mechanization. The [cited Zenodo concept record](https://doi.org/10.5281/zenodo.23260696) currently resolves through its API to [version 23484950](https://zenodo.org/records/23484950), version v2.2.0. I downloaded its 20,850,703-byte ZIP and independently verified MD5 `882281371606554a59e2a77b9bc1cf14`. It has no `vendor/td-verification/TD_side.thy` or other populated solver source. Its `.gitmodules` points to [ManuelLerchner/td-verification](https://github.com/ManuelLerchner/td-verification); both the unauthenticated GitHub page and API returned HTTP 404 during this review. I cannot distinguish a private repository from a nonexistent one, but neither is publicly retrievable here. This is required proof code, not optional developer tooling: `src/Abstract_Interpreter/Solver/TD_Solver_Bridge.thy:2` imports `TD.TD_side_Interface`, and lines 26–36 specify the certificate contract consumed by Voblint. Archive the exact modified solver revision, including its license, and verify the archived bundle from a clean directory. A public main repository alone does not repair this missing dependency.

2. **The archive is not a reproducible snapshot of this paper's experiments.** Location: §7, pp. 13–14, especially the registered-output claim and Table 3. The checked ZIP root is `ManuelLerchner-Voblint-Verification-Master-Thesis-9f92b86/`; it lacks `paper/main.tex`, the paper build/check tasks, and the `ctx-mutual-none`/`ctx-mutual-k2` registrations used by Table 3. The source soundness and non-vacuity declarations are present, so this is a version-alignment defect rather than absence of the entire formalization. Publish an immutable release containing the submitted paper, its claim registrations, generated evidence, profiling snapshot, and the solver revision; cite its version DOI or exact tag. Include a compact command list for the 13 claims. The current prepared checkout reproduces them, but that does not make them reproducible from the cited ZIP.

## Minor comments

1. **State the benchmark exclusion and denominator explicitly.** Location: §7, p. 14, running-time paragraph (`paper/sections/evaluation.tex:78–84`). I independently reduced the pinned snapshot `pages/data/profiling/2026-10-21-17fcb363d.json`: it contains 380 fixtures, 5,514 successful rows, 165 invalid rows, and 21 timeouts. Removing the invalid rows leaves 369 fixtures and 5,535 cases, matching the paper. All timeouts use entry-state contexts. The successful-case median is 0.235 ms and p95 1.48 ms; the paper's 0.23 is its two-decimal formatting. Say that 11 invalid fixtures were excluded and that timing quantiles cover successful solves. “369 fixtures that set no timeout” omits the additional exclusion, and “over these 5,535 cases” obscures the quantile population. This is a reporting clarification; the underlying counts reconcile. The measurements themselves were not rerun.

2. **Separate the generic remainder obligation from the concrete theorem discharging it.** Location: §7, p. 13 (`paper/sections/evaluation.tex:31–33`). `congruence_mod_sound` is a proved lemma for the implemented operator at `src/Analyses/Congruence/Congruence_Arithmetic.thy:766`, used in the interpretation around line 853. Calling that named lemma “an assumption of the locale” blurs the obligation and its discharge. State that the domain must satisfy the generic remainder-soundness obligation and that `congruence_mod_sound` discharges it for the shipped operator. The counterexample theorem's substantive conclusion remains supported.

3. **Expose a paper-sized verification command.** Location: §7, p. 13, statement about registered outputs. The advertised `thesis-claims` checks the entire thesis manifest, whereas `paper-check` checks snippets and bibliography only (`pixi.toml:168`). A paper-specific target selecting these 13 claims and checking generated tables/statistics would let reviewers reproduce the evidence without navigating the thesis workflow. The present commands work locally; this is usability and drift protection, not an observed output mismatch.
