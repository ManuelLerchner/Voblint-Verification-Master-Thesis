\subparagraph*{Design choices and their alternatives.}
Four choices shaped the proof. Only for the first was an alternative
implemented and abandoned.
\begin{itemize}
  \item \emph{Activation traces as the soundness target.} A first prototype
    used whole-program executions with calls inlined. To account for one call,
    the proof built a separate execution from the callee's entry and spliced it
    into the caller's run. This handled single calls but did not reflect the
    call stack and was hard to extend to recursion. The obvious alternative,
    which we did not implement, is the graph semantics itself, with a frame
    stack whose frames carry a ghost context. Its soundness proof would carry an invariant over
    the whole stack. Activation traces turn it into a fact about the caller
    chain, recovered through $\mathit{caller\_of}$, and keep contexts out of
    the concrete semantics, so the policy can be a parameter.
  \item \emph{Contexts as a relation.} The unit and call-string policies are
    functions and discharge \oblig{Total} once for every cover. The relational
    form is needed for an enter that returns overlapping alternatives and for
    the entry-state policy. That policy admits no context for stores the
    analysis excludes, and it proves \oblig{Total} from the solution.
  \item \emph{The solver as a parameter.} The analysis locale assumes four
    facts about a solver instead of reasoning about the top-down solver's run.
    The vendored solver discharges them under all five update rules, and the
    semantic proofs never unfold its definition.
  \item \emph{Two-default executable states.} Soundness is stated over total
    functions on variable names. The solver runs on a quotient
    type~\cite{huffman13} of defaults and a finite override list, as in
    Concrete Semantics~\cite[§13.6]{nipkow14}, with separate defaults for
    locals ($\top$) and zero-initialized globals ($0^\sharp$)
    (\isaname{exec_local_spec_sound}).
\end{itemize}

The coverage contract, the analysis contract, the routing conditions, and
the certified solver are each a locale~\cite{ballarin14}, and a domain is
registered with one locale interpretation per context policy.

\subparagraph*{Feedback on the proof assistant.}
Two points cost effort that the tooling could reduce. First, HOL admits only
terminating recursion. The solver is therefore defined with a domain predicate
and an executable variant that returns only when the recursion finishes, and a
returned run must be transported to the logical definition. A lemma added to
the vendored solver proves this transport once (\isaname{solve_dom_of_solve_c}).
Second, code generation turns finite sets and maps into lists that every
lookup scans. One definition recompiled the whole program at every equation
evaluation until a proved code equation replaced it, without changing any
theorem. CPU profiles attribute most of the remaining solve time to list
membership and lookup. The Collections Framework or the Containers library
could replace these structures in the code setup alone, without touching the
soundness proofs. We leave this to future work.
