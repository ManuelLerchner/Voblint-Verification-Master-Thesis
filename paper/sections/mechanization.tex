\subparagraph*{Design choices and their alternatives.}
Besides the relational context policy (\cref{sec:traces}) and the solver
as a parameter (\cref{sec:equations}), two choices shaped the proof. Only for
the first was an alternative implemented and abandoned.
\begin{itemize}
  \item \emph{Activation traces as the soundness target.} A first prototype
    used whole-program executions with calls inlined. To account for one call,
    the proof built a separate execution from the callee's entry and spliced it
    into the caller's run. This handled single calls but did not reflect the
    call stack and was hard to extend to recursion. The obvious alternative,
    which we did not implement, is the graph semantics itself, with a frame
    stack whose frames carry a ghost context. Its soundness proof would carry an invariant over
    the whole stack. Activation traces turn it into a fact about the caller
    chain, recovered through $\mathit{caller\_of}$, and keep contexts out of
    the concrete semantics, so the policy can be a parameter.
  \item \emph{Two-default executable states.} Soundness is stated over total
    functions on variable names; the solver runs on a quotient
    type~\cite{huffman13} of a finite override list with separate defaults
    for locals and zero-initialized globals (\isaname{exec_local_spec_sound}),
    refining the single default of Concrete Semantics~\cite[§13.6]{nipkow14}.
\end{itemize}

The contracts of \cref{sec:traces,sec:equations} and the certified solver
are locales~\cite{ballarin14}; a domain is registered with one locale
interpretation per context policy.

\subparagraph*{Feedback on the proof assistant.}
Two points cost effort that the tooling could reduce. First, functions in Isabelle/HOL are total. A solver that may diverge is
therefore defined with a domain predicate, next to an executable variant that
returns only when the recursion finishes, and a returned run must be
transported to the logical definition. A lemma added to the vendored solver
proves this transport once (\isaname{solve_dom_of_solve_c}).
Second, code generation turns finite sets and maps into lists that every
lookup scans, and CPU profiles attribute most of the solve time to these scans.
The Containers library could replace them in the code setup alone, without
touching the proofs; we leave this to future work.
