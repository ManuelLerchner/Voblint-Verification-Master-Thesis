changes made for this work and proposed upstream. They restore the build
under Isabelle2025-2, remove from the widening and narrowing classes the
stabilization assumptions that only termination proofs use, rename clashing
names, and add facts such as \isaname{solve_dom_of_solve_c}. None changes the
algorithm.
Neither Voblint nor the imported solver theories contain \texttt{sorry} or
\texttt{oops}. Code generation emits \stat{generated_ocaml} lines of OCaml. The handwritten
OCaml implementation contains \stat{handwritten_ocaml} lines for parsing,
report printing, and the trace hook. A full build takes several minutes on
an Apple M4 Pro laptop.

\subparagraph*{Design choices and their alternatives.}
Besides the relational context policy (\cref{sec:traces}) and the solver
as a parameter (\cref{sec:equations}), two choices shaped the proof.
\begin{itemize}
  \item \emph{Activation traces as the soundness target.} A first prototype
    used whole-program executions with calls inlined. Its proof spliced
    a callee execution into the caller's run, which was hard to extend to
    recursion. An unimplemented alternative would annotate graph-semantics
    stack frames with ghost contexts and maintain an invariant over the stack.
    With activation traces, the invariant concerns the caller chain recovered
    by $\mathit{caller\_of}$; contexts remain a separate policy parameter.
  \item \emph{Two-default executable states.} Soundness is stated over total
    functions on variable names; the solver runs on a quotient
    type~\cite{huffman13} of a finite override list with separate defaults
    for locals and zero-initialized globals (\isaname{exec_local_spec_sound}),
    refining the single default of Concrete Semantics~\cite[§13.6]{nipkow14}.
\end{itemize}

\subparagraph*{Feedback on the proof assistant.}
Connecting the executable solver to its logical definition required a
separate proof. Functions in Isabelle/HOL are total, so the potentially
diverging solver has a domain predicate. For a terminating execution, we must
show that the logical solver is defined. The added lemma
\isaname{solve_dom_of_solve_c} establishes this implication.
Code generation also turns finite sets and maps into lists that every
lookup scans, and CPU profiles attribute most of the solving time to these scans.
Replacing these list representations through the Containers library is a
possible optimization that we have not evaluated.
