We follow the program of \cref{fig:running} through the analyzer, with
intervals and entry-state contexts. The source program is compiled to a
procedure-aware control-flow graph (CFG). Each procedure $p$ has an entry node
$\ctor{FunctionEntry}\;p$ and a result node $\ctor{FunctionResult}\;p$. The
graph $g$ has two kinds of edges. An \emph{intraprocedural} edge
$(u, a, v) \in \mathit{intra}\;g$ carries an action $a$, such as an
assignment or a guard. A \emph{call} edge
$(u, e, \ctor{FunctionEntry}\;p, k) \in \mathit{calls}\;g$ leads from the call
site $u$ into $p$ and names the continuation $k$ at which the caller resumes.
A predicate $\Glob$ tells which variables are global. A proved forward
simulation relates every source execution to a graph execution with the same
store (\cref{sec:theorem}).

From the graph, the analyzer generates inequations over \emph{local unknowns}
$(v, c)$ for a node $v$ and a context $c$, and over \emph{global unknowns}
without a program point. At the call \texttt{a = bump(5)}, the right-hand side
of the continuation reads the caller's state and applies the analysis's
\emph{enter} operation. Enter returns an \emph{entry pair} of a resume state,
which describes the caller, and an entry state, which binds \texttt{n} to
$[5,5]$. The entry state is \emph{routed} to the callee context $c_1 = [5,5]$.
Which contexts a callee is entered in becomes known only while the equations
are solved, so the callee's entry equation cannot list its callers. The call
instead publishes its entry state as a side effect to a global \emph{seed}
unknown for $(\texttt{bump}, c_1)$, which the entry equation of \texttt{bump}
in $c_1$ reads. The continuation then reads the callee's exit state in $c_1$
and \emph{combines} it with the resume state. The second call routes to
$c_2 = [4,4]$, so both checks are proved.

For these per-context states to mean something, the concrete semantics has to
say which stores belong to $c_1$. Activation traces (\cref{sec:traces}) supply
this. The trace of the activation \texttt{bump(5)} records its caller, the
context policy admits it in $c_1$, and the \emph{activation collecting
semantics} $\ActColl(v, c)$ collects the final stores of the traces that end
at $v$ and carry $c$. The \emph{node collecting semantics} $\NodeColl(v)$
collects them regardless of context. A report $\mathit{res}$ of the analyzer
defines two sets at each node $v$. The report set $\Report_{\mathit{res}}(v)$
contains the stores that some state of the report at $v$ describes, in any
context. The verdict set $\Verd_{\mathit{res}}(v)$ contains the stores in which
every definite verdict at $v$ holds. The soundness argument is a chain of
inclusions at every node:
\begin{equation}
\label{eq:chain}
\text{reached stores}
\;\subseteq\; \NodeColl(v)
\;=\; \textstyle\bigcup_c \ActColl(v, c)
\;\subseteq\; \Report_{\mathit{res}}(v)
\;\subseteq\; \Verd_{\mathit{res}}(v).
\end{equation}
Each inclusion may add stores that no execution reaches, which costs
precision. None may lose a reached store. The contexts appear in the middle of
the chain and disappear at its ends. The end-to-end theorem
(\cref{sec:theorem}) states the outer inclusions for every report the
analyzer returns.
