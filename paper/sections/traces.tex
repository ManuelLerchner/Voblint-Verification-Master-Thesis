\section{Activation Traces and the Coverage Contract}
\label{sec:traces}

A context-sensitive analysis claims, for each node $v$ and context $c$, a set
of stores. To check such a claim, we need the set of stores that executions
bring to $v$ \emph{in context $c$}. Neither a graph execution nor its flat list
of visited node--store pairs provides it. A frame of the runtime stack holds
only what is needed to resume the caller and disappears at the return, and the
flat list interleaves the steps of all activations. Grouping a run by
activation makes the missing structure explicit: each call starts a new
activation attached to its caller, and each return composes the finished
callee back into that caller.

\subsection{Activation traces}

An \emph{activation path} is a list of node--store pairs visited by one
activation. An activation trace has one constructor for each way an activation
begins or continues (\isaname{activation_trace}):
\snippet{activation_trace}
\noindent $\ctor{Root}~\pi$ is the activation of \texttt{main}.
$\ctor{Call}~t'~\pi$ is a callee created by the caller trace $t'$, frozen at
the call site. $\ctor{Resume}~t'~t''~\pi$ continues $t'$ past the call that
produced the finished callee $t''$. Observers return the last node
$\mathit{sink\_node}\;t$, its store $\mathit{sink\_store}\;t$, and the caller
$\mathit{caller\_of}\;t$, which a $\ctor{Root}$ lacks.

The datatype admits terms that no execution produces, for instance a
$\ctor{Resume}$ pairing a caller with a callee that another activation
created. The set $\Traces_{\Glob,g,S}$ of \emph{valid} traces of a graph $g$
with initial stores $S$ is therefore defined inductively, by four rules that
mirror the rules of graph execution (\isaname{valid_activation_trace}):
\begin{gather*}
\frac{s \in S}{\ctor{Root}\,[(\mathit{entry}_g, s)] \in \Traces}
\\[1ex]
\frac{t \in \Traces \quad (\mathit{sink\_node}\;t, a, v) \in \mathit{intra}\;g \quad s' \in \mathit{step}_a(\mathit{sink\_store}\;t)}{\mathit{extend}\;t\;(v, s') \in \Traces}
\\[1ex]
\frac{t \in \Traces \quad \mathit{sink\_node}\;t \xrightarrow{\;e\;} \ctor{FunctionEntry}\;p}{\ctor{Call}\;t\;[(\ctor{FunctionEntry}\;p,\; \mathit{enter}_e(\mathit{sink\_store}\;t))] \in \Traces}
\\[1ex]
\frac{t'' \in \Traces \quad \mathit{caller\_of}\;t'' = t' \quad \mathit{sink\_node}\;t'' = \ctor{FunctionResult}\;p}{\ctor{Resume}\;t'\;t''\;\bigl(\mathit{path\_of}\;t' \mathbin{@} [(k,\; \mathit{combine}(\mathit{sink\_store}\;t',\, \mathit{sink\_store}\;t''))]\bigr) \in \Traces}
\end{gather*}
In the call rule, $e$ is a call edge into $p$, and $\mathit{enter}_e$ binds the
formals to the arguments. In the return rule, $k$ is the continuation that the
call edge from $t'$'s call site names, and $\mathit{combine}$ takes the
caller's locals and the callee's globals and assigns the return value to the
call's destination (\isaname{combine_collect}). Because a callee
stores its creator exactly, a return resumes exactly the activation that made
the call, without searching for a compatible frame.

Every finite source execution of a well-formed program yields a valid trace
that ends at the corresponding node with the same store and whose chain of
callers represents the runtime frame stack
(\isaname{source_run_has_activation_trace}). Collecting the final stores of
valid traces per node gives the \emph{node collecting semantics}
$\NodeColl_{\Glob,g,S}(v)$ (\isaname{node_collect}).

This design adapts the local traces of Schwarz et al.~\cite{schwarz21}, which
give one thread's view of a concurrent execution. $\ctor{Root}$ corresponds to
an initial trace, $\ctor{Call}$ to thread creation, and $\ctor{Resume}$ to the
binary rule for acquiring a lock, which incorporates a second trace. The
objects differ: a local trace is an acyclic graph of events of several
threads, whereas an activation trace holds the path of one activation, refers
to at most two other traces, and its $\ctor{Resume}$ accepts only the callee
that the activation itself created.

\subsection{Calling contexts as a relation}

An analysis chooses a callee's context at the call. With call strings of
length one, it is the call site; with entry-state contexts, the abstract values
of the formals at entry. A \emph{context policy} fixes this choice for every
concrete call. It maps a call site $u$, a caller context $c$, a description of
the call, the caller's store, and the entered store to the \emph{set} of callee
contexts it admits (\isaname{context_policy}):
\snippet{context_policy}
\noindent A set, because Goblint's \emph{enter} may return several
alternatives for one call, each routed separately. When the alternatives
overlap, one concrete call belongs to several contexts
(\isaname{ov_two_contexts_admitted}). A set may also be empty, for instance at
a call the analysis considers unreachable.

The contexts of a trace follow by applying the policy along the calls that
created it (\isaname{activation_context_rel}). The root carries the initial
context $c_0$, a callee carries every $c'$ that the policy admits for its call
from some context of its caller, and local steps and resumptions keep the
caller's contexts. The traces themselves store no context, so the policy is a
parameter of every theorem. The \emph{activation collecting semantics}
collects the final stores of valid traces that end at $v$ and carry $c$
(\isaname{activation_collect}):
\[
\ActColl_{\Glob,\adm,c_0,g,S}(v, c) \;=\; \{\, \mathit{sink\_store}\;t \mid t \in \Traces_{\Glob,g,S},\; \mathit{sink\_node}\;t = v,\; t \text{ carries } c \,\}.
\]
In the running example, the final store of \texttt{bump(5)} lies in
$\ActColl(\ctor{FunctionResult}\;\texttt{bump}, [5,5])$ and that of
\texttt{bump(4)} in $\ActColl(\ctor{FunctionResult}\;\texttt{bump}, [4,4])$,
whereas $\NodeColl$ at that node contains both.

\subsection{The coverage contract}

An analysis result is sound if, at every node and context, it accounts for
the activation collecting semantics. We state this over a \emph{cover}, a
function assigning a set of stores to each node and context. Since valid
traces grow by four rules, it suffices to check the cover against each rule
once. For a call edge from $u$ into $p$ with continuation $k$, the contract
\isaname{activation_coverage} requires:
\begin{align*}
  &\oblig{Init} && s \in S \implies s \in \cover(\mathit{entry}_g, c_0)\\
  &\oblig{Intra} && (u, a, v) \in \mathit{intra}\;g,\; s \in \cover(u, c),\; s' \in \mathit{step}_a(s) \implies s' \in \cover(v, c)\\
  &\oblig{Call} && s \in \cover(u, c),\; c' \text{ admitted from } s\\
  &&&\qquad\implies \mathit{enter}(s) \in \cover(\ctor{FunctionEntry}\;p, c')\\
  &\oblig{Return} && s \in \cover(u, c),\; c' \text{ admitted from } s,\; t \in \cover(\ctor{FunctionResult}\;p, c')\\
  &&&\qquad\implies \mathit{combine}(s, t) \in \cover(k, c)\\
  &\oblig{Total} && s \in \cover(u, c) \implies \text{some } c' \text{ is admitted from } s
\end{align*}
Here ``$c'$ admitted from $s$'' means that the policy admits $c'$ for the call
from $s$ in context $c$. \oblig{Total} closes a gap the other four leave. If a
call from a covered store is admitted in no context, \oblig{Call} and
\oblig{Return} hold vacuously, nothing places the store after the return at
the continuation, and yet the resumed caller still carries its contexts there.
Without \oblig{Total}, the contract admits a cover that misses a store the
program reaches (\isaname{total_dropped_unsound}). \oblig{Total} asks only
about covered stores, because an entry-state policy admits no context for
stores the analysis has excluded. Call strings and the unit policy meet it for
every cover (\isaname{call_context_total_on_of_fun}).

\begin{theorem}[Context-indexed soundness, \isaname{activation_collect_sound}]
\label{thm:contract}
If a cover meets the five obligations, then
$\ActColl(v, c) \subseteq \cover(v, c)$ for every node $v$ and context $c$.
\end{theorem}
\snippet{activation_collect_sound}

The proof is an induction over the four rules of valid traces, one obligation
per rule, with the invariant that every valid trace carries some context and
that its final store is covered in every context it carries
(\isaname{valid_activation_trace_covered}). The return case is the one that needs the
structure of traces: the caller's context must be the one in which the call
was made, and $\mathit{caller\_of}$ supplies exactly that caller. Within the
contract, \oblig{Total} also gives every valid trace a context, so splitting by
context loses nothing (\isaname{node_collect_eq_Union_activation_collect}):
\[
\NodeColl(v) \;=\; \textstyle\bigcup_c \ActColl(v, c).
\]
This completes the concrete half of the argument. An analysis never reasons
about whole runs. It only has to produce store sets that each kind of step
preserves, and \cref{sec:equations} shows that a solved equation system does.
