Thesis hook

Soundness is stated against CFG collecting semantics at every program point (cfg_collect in Collecting/). The analyzer’s post-fixpoint soundly over-approximates that semantics. The core layer supplies the graph and path vocabulary the collecting and equation proofs share.

01CFG record

src/CFG/CFG_Def.thy — programs as directed graphs with labelled edges.

Program points

type_synonym pp = nat

Fresh naturals allocated during compile. Each command’s subgraph occupies a disjoint interval [n, n') of the counter.

Edge actions

datatype edge_action

EA_Nop
| EA_Assign   vname aexp    -- s(x := aval a s)
| EA_Assume   bexp          -- keep states with bval b s
| EA_AssumeNot bexp         -- keep states with ¬ bval b s

Branching in IF / WHILE becomes assumption edges (store filters), not extra control-flow syntax.

CFG record (AFP graph extension)

record cfg = "(pp, edge_action) graph" +
  cfg_entry :: pp
  cfg_exit  :: pp

definition mk_cfg :: "pp => pp => (pp * edge_action * pp) set => cfg"
  -- auto-computes nodes so valid_graph holds

Selectors nodes g and edges g come from AFP Dijkstra_Shortest_Path.Graph. Prefer mk_cfg en ex E over manual record construction.

Derived API (selected)

NameRole
cfg_entry g / cfg_exit gUnique entry and exit program points.
edges gSet of triples (u, a, v): from u to v performing action a.
predecessors g vIncoming labelled edges; finite when edges g is finite (finite_predecessors).
predecessor_list g vSorted list view for Finite_Set.fold in the equation system.
offset_edges k EAffine shift: every endpoint in E is incremented by k (actions unchanged).

Core lemmas

  • mk_cfg_valid_graph Building a cfg from entry, exit, and edges always yields a well-formed graph.
  • finite_predecessors Finite incoming edges at each pp — needed for Finite_Set.fold in rhs.
  • offset_edges_Un Union of shifted edge sets shifts each component.
  • in_offset_edges_iff Membership in offset_edges k E iff the unshifted triple is in E.

02Paths & offsets

src/CFG/CFG_Path.thy — inductive labelled paths (FormalSSA-style library).

cfg_path g u es v

There is a walk from u to v in g, recording each step as (edge_action, next_pp) in list es.

inductive cfg_path :: "cfg => pp => (edge_action * pp) list => pp => bool" where
  empty: "cfg_path g v [] v"
| step:  "(u, a, w) : edges g ==> cfg_path g w es v
          ==> cfg_path g u ((a, w) # es) v"

abbreviation cfg_reaches :: "cfg => pp => pp => bool"  ("_ |- _ -->* _")
  -- exists es. cfg_path g u es v

Edge actions are stored on the path because transfer-function composition (equation soundness and edges_collect in Collecting/) must know which action fired at each step.

flowchart LR u(("u")) w(("w")) v(("v")) u -- "(a, w)" --> w w -- "es …" --> v

Offset infrastructure

When compile c n runs at n > 0, the subgraph is the n = 0 shape with all program points shifted. Paths lift and lower through the same offset.

DefinitionMeaning
offset_path k esMap each (a, p) to (a, p + k) in the step list.
unoffset_path k esInverse: strip k from every target pp in es.
offset_edges k EShift all edge endpoints in E (defined in CFG_Def).
LEMMA cfg_path_offset

Paths in a sub-CFG (compiled at offset 0) lift to paths in the parent graph after shifting program points and edge endpoints by k. 

cfg_path (mk_cfg ent ex E) u es v
  ==> cfg_path (mk_cfg (ent + k) (ex + k) (offset_edges k E))
              (u + k) (offset_path k es) (v + k)

Used in CFG_Compound_Paths.thy for Seq / If / While compilation proofs.

LEMMA cfg_path_offset_back

Conversely, a path in the shifted compound graph that stays above offset k projects to a path in the original sub-edge set.

Requires u, v ≥ k and edges G = offset_edges k E; uses unoffset_path.

Path algebra (selected)

  • cfg_path_append If there is a path u → w and w → v, their step lists form a path u → v.
  • cfg_reaches_trans Reachability in the CFG is transitive.
  • cfg_path_split_last Decompose a non-empty path into a prefix path and one final edge (loop proofs).
  • offset_path_append offset_path k distributes over appending step lists.

03Compilation

src/CFG/IMP2_to_CFG.thy — structural translation with a fresh program-point counter.

compile c n and to_cfg c

compile returns (n', entry, exit, edges)

  • n — first free pp id; all allocated ids lie in [n, n').
  • entry, exit — unique entry/exit of command c's subgraph.
  • edges — labelled edges for c only (glue edges at composition sites).
definition to_cfg :: "com => cfg" where
  "to_cfg c =
     (let (_, en, ex, E) = compile c 0
      in  mk_cfg en ex E)"

Global entry/exit: cfg_entry (to_cfg c), cfg_exit (to_cfg c).

flowchart TD subgraph skip ["SKIP"] s0(("n")) -- EA_Nop --> s1(("n+1")) end subgraph assign ["x ::= a"] a0(("n")) -- "EA_Assign x a" --> a1(("n+1")) end subgraph seq ["c1 ;; c2"] e1["c1 entry"] --> x1["c1 …"] --> ex1["c1 exit"] ex1 -- EA_Nop --> e2["c2 entry"] --> x2["c2 …"] --> ex2["c2 exit"] end subgraph ifc ["IF b THEN c1 ELSE c2"] en(("entry")) en -- "EA_Assume b" --> b1["c1"] en -- "EA_AssumeNot b" --> b2["c2"] b1 -- EA_Nop --> xn(("exit")) b2 -- EA_Nop --> xn end subgraph wh ["WHILE b DO c"] head(("head")) head -- "EA_Assume b" --> body["body"] body -- EA_Nop --> head head -- "EA_AssumeNot b" --> ex(("exit")) end

Compilation lemmas (proved)

  • compile_fresh All pps allocated by compile are fresh relative to the start counter.
  • compile_ge The counter strictly increases — supports induction on command structure.
  • compile_entry_ne_exit Every compiled command subgraph has distinct entry and exit nodes.
  • compile_finite Each compile produces finitely many edges.
  • to_cfg_finite to_cfg c has finite edges — enables collecting lfp and folds.
  • compile_add_offset / compile_from_0_offsets compile c (n+k) is compile c n with all pps and edges shifted by k.
  • to_cfg_compile Rewrite to_cfg c as the compile c 0 quadruple for proofs.
Nested compile at offset k > 0

Sub-commands compiled inside Seq / If / While appear as offset_edges k (edges (to_cfg c)) in the parent graph. Path proofs combine cfg_path_offset with edge-set monotonicity lemmas in Collecting/CFG_Compound_Paths.thy — not repeated here.
