Goblint Formalization · Examples

Executable examples off the proof spine

Theories under src/Examples/ are smoke tests and small demonstrations: code generation, sanity checks on collecting vs paths, runnable abstract analyses, and CFG visualization. They live in the same Isabelle session as the main formalization but are not imported by Goblint_Formalization.thy — the verified soundness chain does not depend on them.

⊞Example theories at a glance

All five are listed in ROOT under session Goblint_Formalization (directories "Examples"). You can build the full session or stop at a single example theory (see How to build).

Theory Imports (direct) Demonstrates
Example_Sign_Analysis Sign_Domain, IMP2_to_CFG, TD_Interface Runnable sign analysis: CFG compile, transfer-fn spot checks, TD_plain_Interp_solve on a pair abstract state.
Example_Interval_Analysis Interval_Domain, IMP2_to_CFG, TD_Interface Same toy program with interval domain; tight [5,5] / [10,10] results; executable TD on a pair type.

Not on the core proof spine

Goblint_Formalization.thy imports IMP2, CFG, domains, equations, TD bridge, and Pipeline — not the example theories. Examples reuse those layers for value / term checks and pedagogy; closing the main theorems does not require processing them.

01Example_Sign_Analysis

Sign analysis of a two-assignment IMP2 program.

Program

x := 5;
y := x + x

Imports

  • Sign_Domain — sign abstract values and transfer functions
  • IMP2_to_CFG — to_cfg, compile
  • TD_Interface — td_analyse, make_rhs_tree

What it demonstrates

  • Type-checked pipeline stack — term for td_analyse and make_rhs_tree on the real sign domain (same API as proofs).
  • CFG inspection — value on compile, entry/exit program points, and edge sets.
  • Transfer-function spot checks — aval_sign, assign_sign on small states.
  • Executable TD solve — projects sign abs_state to datatype ss (pair) so the AFP refined solver can compare answers; hand-built strategy trees mirror the CFG; TD_plain_Interp_solve at exit and entry.

Note: full value on arbitrary vname ⇒ sign maps is not generated — Isabelle lacks executable equality on function types. The pair encoding is the standard workaround (see theory header).

Source: src/Examples/Example_Sign_Analysis.thy

02Example_Interval_Analysis

Interval analysis on the same toy program as the sign example.

Program

x := 5;
y := x + x

Expected: x ∈ [5,5], y ∈ [10,10] at exit.

Imports

  • Interval_Domain — interval lattice and ivl_tf
  • IMP2_to_CFG
  • TD_Interface

What it demonstrates

  • Interval transfer spot checks — aval_ivl, assign_ivl yielding singleton intervals where precision allows.
  • Same pipeline wiring — term for td_analyse with ivl_tf and interval join/bot/init.
  • Executable solve on iss — pair type iss with order/bot instances, strategy trees, and TD_plain_Interp_solve (parallel structure to the sign example).

Source: src/Examples/Example_Interval_Analysis.thy

03Example_CFG_Collecting_Equiv

CFG collecting semantics on a concrete terminating program.

Program

x := 5;
y := x + 1

Exit store: {x ↦ 5, y ↦ 6} from initial λ_. 0.

Imports

  • CFG_Runs_To_Bridge — small-step ↔ cfg_collect, runs_to_def

What it demonstrates

  • Operational → collecting bridge — small-step star to SKIP, then small_step_runs_to for runs_to.
  • Exit membership in cfg_collect — corollary that the final store lies in collecting semantics at cfg_exit.
  • Compiled CFG shape — value on to_cfg (PP0–PP3 with assign/nop edges).

This is a sanity check on the CFG collecting layer used in the main soundness story (CFG collecting walkthrough), not a separate proof obligation.

Source: src/Examples/Example_CFG_Collecting_Equiv.thy

04Example_GraphViz

Visual CFG dumps for small IMP2 programs.

Imports

  • CFG_GraphViz — to_graphviz code generation
  • IMP2_to_CFG — to_cfg

What it demonstrates

  • Four sample programs — straight-line, absolute-value if, countdown while, nested loop with branch.
  • ML block output — writeln_dot prints DOT to the Isabelle output panel / build log; paste into any Graphviz renderer.
  • Extensibility — add a definition and one writeln_dot line in the ML section at the bottom of the theory.

Source: src/Examples/Example_GraphViz.thy

05Example_NonTerminating_Safe

Per-program-point soundness when the program never finishes.

Imports

  • Pipeline — pipeline_sound_runs_to, pipeline_sound_path, run_analysis

What it demonstrates

  • Non-terminating run, vacuous exit soundness — x := 10; while True do skip: proves no runs_to, so pipeline_sound_runs_to conclusion is empty (premise never holds).
  • Path-based soundness still applies — nonterm_safe_at_every_pp instantiates pipeline_sound_path at every CFG-reachable program point (e.g. right after the assignment).
  • Diverging loop with state mutation — x := 0; while True do x := x + 1: countably infinite reachable stores at the loop body; exit-only theorem still vacuous; path theorem constrains abstract states at interior points (domain-parametric).

Connects to the pipeline narrative: soundness narrative and pipeline_sound_path in src/Pipeline/Pipeline.thy.

Source: src/Examples/Example_NonTerminating_Safe.thy

⚙How to build

From the repository root. Examples share session Goblint_Formalization with the main theories; AFP and vendored TD paths match the project default.

Full session (all theories including examples)

isabelle build -v \
  -d ~/afp/thys \
  -d vendor/td-verification \
  -D . \
  Goblint_Formalization

Single example theory (faster incremental check)

Use -e THEORY to build only what is needed up to that theory name (as listed in ROOT): 

isabelle build -v -d ~/afp/thys -d vendor/td-verification -D . \
  -e Example_Sign_Analysis Goblint_Formalization

isabelle build -v -d ~/afp/thys -d vendor/td-verification -D . \
  -e Example_Interval_Analysis Goblint_Formalization

isabelle build -v -d ~/afp/thys -d vendor/td-verification -D . \
  -e Example_CFG_Collecting_Equiv Goblint_Formalization

isabelle build -v -d ~/afp/thys -d vendor/td-verification -D . \
  -e Example_GraphViz Goblint_Formalization

isabelle build -v -d ~/afp/thys -d vendor/td-verification -D . \
  -e Example_NonTerminating_Safe Goblint_Formalization
Interactive development

Open any example in jEdit / Isabelle/jEdit with session Goblint_Formalization and run value / ML blocks locally. Example_GraphViz prints DOT during build; sign/interval examples print solver results in the output panel.
