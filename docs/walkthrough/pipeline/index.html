Voblint Formalization · Main narrative

End-to-end analyzer pipeline

How IMP2 source becomes a sound abstract result: compile to a CFG, build constraint right-hand sides, run the vendored top-down solver, and show that the post-fixpoint γ-concretization over-approximates cfg_collect at every program point — not only at exit. The collecting semantics is the specification; runs_to is exit sugar linked to small-step termination. 

x ::= N 1;;
WHILE Less (N 0) (V x) DO
  x ::= Plus (V x) (N (-1))

Initial store s = (λ_. 0); small-step execution terminates with t x = 0. The sign abstract exit for x must concretize to a set containing 0 — the headline theorem voblint_sign_sound (closed).

00Running example

One program traced through the full chain. Operational reading uses small_step ((c,s) → … → (SKIP, t)); the formal spec uses cfg_collect and runs_to. For the same program (and a straight-line companion) with named lemmas at each layer, see Running example — lemma trace (Isabelle snippets for Programs A–C; per-layer callouts on each walkthrough page).

Program c

x ::= N 1;;
WHILE Less (N 0) (V x) DO
  x ::= Plus (V x) (N (-1))

Concrete execution

s = (λ_. 0)
-- small_step star terminates -->
t x = 0

runs_to c s t holds (definitional: membership in cfg_collect (to_cfg c) {s} (cfg_exit (to_cfg c))). Bridge: runs_to_iff_small_step in CFG_Runs_To_Bridge.thy.

Target (sign, exit)
t ∈ sign_domain.gamma_state
      (run_analysis (sign_analysis_config s) c
         (cfg_exit (to_cfg c)))

So the abstract sign at exit for x is in {SZero, STop} — its concretization contains 0. Proved as voblint_sign_sound via sign_pipeline_sound.

01Invariant soundness

pipeline_invariant_sound in src/Pipeline/Pipeline.thy — the primary end-to-end statement. Point-map soundness at every program point; exit-only results are corollaries.

Thmpipeline_invariant_sound

Main soundness theorem. At every program point, every concrete store allowed by CFG collecting semantics is also contained in the concretization of the analyzer’s abstract state at that point. 

∀ v. cfg_collect (to_cfg c) {s} v
      ≤ γ_state (run_analysis cfg c v)

Assumes a generic analysis_config: sound_domain (ac_gamma cfg), domain_transfer_sound for edge transformers, initial store in γ of ac_init cfg, idempotent join (for Finite_Set.fold), join_eq / bot_eq matching ac_join / ac_bot, and TD solver hypothesis ⋀v. TD_plain.solve_dom (make_rhs_tree …) v (P1).

Proof spine (inside the lemma)

(1) td_analyse_collect_sound_at — per-pp TD result ⊆ γ at queried v (TD_Soundness.thy)
(2) post_fixpoint_sound_at — path-shaped rhs/step premises ⇒ cfg_collect at v
(3) Pointwise transfer soundness + monotone rhs (packaged in domain_transfer_sound)
  • td_analyse_collect_sound_at TD_Soundness.thy The TD solver’s result at a queried point over-approximates collecting semantics there.
  • post_fixpoint_sound_at Constraint_System_Sound.thy If the abstract environment satisfies the one-step rhs inequality at v, then cfg_collect at v stays inside γ.
  • sign_pipeline_invariant_sound Same invariant theorem with sign domain configuration and transfers plugged in.
Design choice

Earlier AST-only exit annotations cannot express assignment soundness in general. The CFG + post-fixpoint story is the main theorem; see docs/PROOF_OVERVIEW.md (“Why not AST annotations”).

02Path soundness

pipeline_sound_path — soundness along any CFG path, including non-terminating programs at intermediate points (Example_NonTerminating_Safe.thy).

Thmpipeline_sound_path

Along any CFG path from entry, if a concrete store arises by folding edge transfers along that path, the analyzer’s abstract state at the path’s end concretizes to a set that contains it — without assuming the program terminates. 

cfg_path (to_cfg c) (cfg_entry (to_cfg c)) es v
⟹ t ∈ edges_collect es {s}
⟹ t ∈ γ_state (run_analysis cfg c v)

Follows from pipeline_invariant_sound and path_sound_cfg_collect (CFG_Path_Bridge.thy): path-collected stores sit inside cfg_collect at v.

Path infrastructure

ConceptIn words
cfg_pathLabelled walk from entry recording each edge_action (CFG_Path.thy).
edges_collectApply edge transfers along a path’s action list to a store set.
cfg_collect_eq_cfg_edges_collectGlobal fixpoint collecting equals union over all paths to v.
path_sound_cfg_collectPath-folded stores are contained in cfg_collect at the path end.
Non-termination

If a loop never exits, runs_to gives no conclusion — but pipeline_sound_path still bounds stores reachable inside the loop (e.g. x = 10 after x := 10; while True do skip). See the exit vs path diagram (Example_NonTerminating_Safe).

03Exit corollaries

For consumers that want “program runs s to t” wording: specialize the invariant to v = cfg_exit (to_cfg c). Primary spec premise is membership in cfg_collect at exit, not a separate operational rule.

Defruns_to CFG_Runs_To_Bridge.thy

“The program can finish at store t” means: t appears in the collecting set at the compiled CFG’s exit node — not a separate big-step rule. 

runs_to c s t  ⟺
  t ∈ cfg_collect (to_cfg c) {s} (cfg_exit (to_cfg c))
Thmpipeline_sound_runs_to

Exit-only soundness: any concrete final store in the collecting semantics at exit is covered by the abstract analysis at the exit program point. 

t ∈ cfg_collect (to_cfg c) {s}
      (cfg_exit (to_cfg c))
⟹ t ∈ γ_state (run_analysis cfg c
      (cfg_exit (to_cfg c)))
Corpipeline_sound_runs_to_runs

Same as above, but the premise is phrased with runs_to for IMP2 consumers who proved small-step termination to SKIP. 

runs_to c s t
⟹ t ∈ γ_state (run_analysis cfg c
      (cfg_exit (to_cfg c)))

Operational link (terminating runs)

  • runs_to_iff_small_step Terminating small-step execution to SKIP is equivalent to exit collecting membership.
  • small_step_runs_to Forward: build runs_to from a small-step star (used in examples).
  • runs_to_small_step Reverse: unpack runs_to into an operational execution trace.

On the running example: prove termination with small-step rules in IMP2, then apply exit corollaries — or use cfg_collect directly as the soundness premise.

04voblint_sign_sound

Top-level thesis entry point in src/Voblint_Formalization.thy. Sign pipeline closed — instantiates generic pipeline lemmas with sign_analysis_config and proved sign transfer functions.

Thmvoblint_sign_sound Voblint_Formalization.thy

Thesis headline (sign). If the program terminates from s to t and the TD solver finishes on the compiled CFG, then the sign analysis at exit concretizes to a set that contains t. 

runs_to c s t
⟹ ⋀v. TD_plain.solve_dom (make_rhs_tree … sign_tf …) v
⟹ t ∈ sign_domain.gamma_state
      (run_analysis (sign_analysis_config s) c
         (cfg_exit (to_cfg c)))

Proof: by (rule sign_pipeline_sound …).

What is proved vs assumed

Discharged in repoExplicit TD hypotheses
sound_domain for sign; sign_tf_sound / domain_transfer_sound; s ∈ γ(ac_init (sign_analysis_config s)); sign_pipeline_sound → sign_analysis_sound → td_solver_sound ⋀v. TD_plain.solve_dom on the generated make_rhs_tree (P1 — operational termination of per-pp solve)

TD hypotheses are operational (“solver covers this CFG”), not gaps in post_fixpoint_sound. See PROOF_OVERVIEW.

End-to-end chain (sign, exit)

t ∈ cfg_collect (to_cfg c) {s} (cfg_exit …) — spec, or runs_to c s t
⊆ γ_state (td_analyse … (cfg_exit …)) — td_analyse_collect_sound_at at exit
run_analysis = td_analyse ∘ sign_analysis_config — Pipeline + TD_Interface
⇒ voblint_sign_sound
Running example conclusion

For s = λ_. 0 and terminating t with t x = 0, the sign analysis at exit puts x in {SZero, STop}, so 0 ∈ γ_sign … — matching the concrete final value.
