The same record works for Sign, Interval, Octagon, …: each domain instantiates the three transformers and proves they are sound w.r.t. gamma_state (in src/Domains/).

One-step operator at node v

For predecessors (u, a, v) ∈ edges g, collect apply_tf tf a (env u) and join with abs_join_set (Finite_Set.fold join bot). At cfg_entry g, also insert the initial abstract state s0.

DEF rhs

One-step abstract update at node v: join the images of all predecessor edges (plus the initial abstract state at entry), using the domain’s join and transfers. 

rhs g tf join_abs bot_abs s0 env v =
  let preds = {(u, a) | u a. (u, a, v) ∈ edges g};
      vals  = image (λ(u, a). apply_tf tf a (env u)) preds;
      base  = if v = cfg_entry g then insert s0 vals else vals
  in  abs_join_set join_abs bot_abs base

Type: pp ⇒ (pp ⇒ 'a abs_state) ⇒ 'a abs_state — the TD_plain locale expects exactly this “environment in, abstract state out” shape.

Supporting lemmas (construction)

  • abs_join_set_empty Joining an empty set of abstract values yields ⊥.
  • rhs_no_predecessors_not_entry Isolated non-entry node with no predecessors gets ⊥ from rhs.
  • rhs_entry_no_predecessors Entry with no predecessors still seeds s0 into the join.
  • mem_image_le_fold Each element in the image is below the finite join fold.
  • fold_join_image_mono Enlarging the set being joined enlarges the fold result (monotonicity).
  • rhs_mono solver prerequisite rhs is monotone in the environment pointwise — required by TD theory.

02Post-fixpoint predicate

is_post_fixpoint means the environment is above the one-step rhs operator at every program point — a standard post-fixpoint of the chaotic iteration.

DEF is_post_fixpoint predicate

An environment is a post-fixpoint when each node’s stored abstract value is at least as informative as applying one rhs step — the solver aims to produce such an env. 

is_post_fixpoint g tf join_abs bot_abs s0 env  ≡
  ∀v. rhs g tf join_abs bot_abs s0 env v ≤ env v

Equivalently: for all nodes v, the rhs join over predecessor transfer images (plus s0 at entry) is below or equal to the stored abstract value env v in the abstract order. Equivalently, env is a post-fixpoint of the one-step operator λenv. λv. rhs … env v.

flowchart LR subgraph op ["One-step operator"] E1["env"] R["rhs g tf join bot s0 env v"] E1 --> R end subgraph pf ["Post-fixpoint"] E2["env v"] R -->|"≤ (abstract order)"| E2 end subgraph collect ["Collecting semantics"] C["cfg_collect g S v
set of concrete stores"] G["gamma_state (env v)"] C -->|"must be ⊆"| G end pf -.->|"post_fixpoint_sound"| collect
Not a fixpoint equation

The formal definition uses rhs … ≤ env v, not equality rhs … = env v. Soundness only needs one-sided inclusion; the TD solver may return a strictly larger (more conservative) abstract state and still satisfy is_post_fixpoint.

03Soundness theorems

Constraint_System_Sound.thy — inside locale sound_domain: transfer-function soundness ⇒ per-edge collecting step ⇒ global cfg_collect inclusion.

Proof spine (inside the file)

  1. edge_collect_apply_tf_sound — one concrete edge step is sound w.r.t. apply_tf.
  2. apply_tf_le_rhs — each predecessor’s transfer image is below the rhs join at v.
  3. collect_pp_abstract_sound — one collecting fixpoint step stays inside γ(env v).
  4. s0_le_rhs_entry — initial abstract s0 is below rhs at entry.
  5. post_fixpoint_sound_at / post_fixpoint_sound — lift to full cfg_collect via lfp.
  6. exit_sound — specialise to the exit program point only.
LEMMA collect_pp_abstract_sound

One step of the collecting fixpoint operator cannot produce stores outside γ of the abstract environment at that program point. 

is_post_fixpoint g tf (⊔) bot s0 env
⟹ collect_pp g (λv. gamma_state (env v)) v ⊆ gamma_state (env v)
THEOREM post_fixpoint_sound_at one program point

Local version used by the TD bridge: path-shaped rhs/step facts at a single v₀ suffice to bound cfg_collect at v₀. 

… rhs_le · step_le · transfer soundness …
⟹ cfg_collect g S v0 ≤ gamma_state (env v0)

Full statement in Constraint_System_Sound.thy; see solver walkthrough.

THEOREM post_fixpoint_sound all program points

A global post-fixpoint environment soundly over-approximates collecting semantics everywhere on the graph. 

is_post_fixpoint g tf (⊔) bot s0 env
⟹ S ≤ gamma_state s0
⟹ ∀v. cfg_collect g S v ≤ gamma_state (env v)

At every program point v, the abstract value env v soundly over-approximates all stores reachable in collecting semantics from initial set S. Uses cfg_collect_def and lfp_lowerbound from the CFG collecting theory imported via CFG_Runs_To_Bridge.

COROLLARY exit_sound exit only

Specialise global soundness to the exit node: any concrete final store in collecting semantics at exit lies in γ of env at exit. 

is_post_fixpoint (to_cfg c) tf (⊔) bot s0 env
⟹ t ∈ cfg_collect (to_cfg c) {s} (cfg_exit (to_cfg c))
⟹ t ∈ gamma_state (env (cfg_exit (to_cfg c)))

Specialises post_fixpoint_sound to the exit node and a singleton initial store {s}. This is the hook used by the pipeline when combining with runs_to / cfg_collect at exit from the collecting layer.

Per-pp vs exit-only
  • post_fixpoint_sound_at — one program point with path-shaped step_le; used by TD_Soundness (TD supplies rhs/step via td_env_at_path_step_le).
  • post_fixpoint_sound — global is_post_fixpoint over all v; still available when you have a full post-fixpoint map.
  • exit_sound — exit node only; exit corollaries and td_solver_sound.
