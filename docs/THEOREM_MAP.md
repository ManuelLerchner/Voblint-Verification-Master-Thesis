# Theorem map

This page maps the main pipeline claims to their checked Isabelle statements.
The theory and theorem names were verified against the theory sources on
2026-10-15. Definitions remain authoritative in the linked theories.

The public theorems are stated about `run_voblint conf ds p`: a configuration
`conf`, the kind declarations `ds` and a surface program `p`. Their stores are
`reaching ds p v`
([`Analysis_Config.thy`](../src/Executable_Surface/CLI/Analysis_Config.thy)),
the stores of `node_collect` over the elaborated graph `elab_cfg p ds` from
`init_stores (kenv_of ds)`, the stores whose globals are zero at their kinds.
Source runs are runs of `pstep (kenv_of ds) (elab_ptable p ds)`, the core
semantics of the program's elaboration. Surface VIMP has no semantics of its
own; that the elaboration gives a surface program its intended meaning is part
of the adequacy argument, not a theorem.

## Public theorems

All in [`Voblint_CLI.Run_Voblint`](../src/Executable_Surface/CLI/Run_Voblint.thy).
Every one assumes `run_voblint conf ds p = Analysed res` and nothing else:
neither well-formedness nor termination is a premise, because `run_voblint`
answers `Malformed_Program` for a program that fails
`wf_program_compile_input_exec`, `Invalid_Activation` for an empty or repeating
activation list, and `Analysed` only where the executable solve returned.

| Theorem | Statement shape |
| --- | --- |
| `run_voblint_sound` (facts `run_voblint_states`, `run_voblint_proved`, `run_voblint_refuted`) | For `s ∈ reaching ds p v`: some `Lifted d ∈ report_states_at res v` has `s ∈ mcp.act_gamma ds (activation_of (conf_analyses conf)) d`; a check with verdict `Decided Check_Proved` has `truthy (eval (check_exp chk) s)` at every reaching store of its point, and `Decided Check_Refuted` its negation. |
| `run_voblint_report_contract` | `valid_activation (conf_analyses conf)`, `wf_program_compile_input_exec p`, `report_config res = conf`, `report_cfg res = elab_cfg p ds`. |
| `run_voblint_report_sound` (facts `run_voblint_PROVED`, `run_voblint_REFUTED`, `run_voblint_DEAD`, `run_voblint_SAFE`) | For `s ∈ reaching ds p v`: `PROVED res v c ⟹ truthy (eval c s)`, `REFUTED res v c ⟹ ¬ truthy (eval c s)`, `DEAD res v ⟹ False`, and `SAFE res v ⟹ ob ∈ obligations_at ds p v ⟹ s ⊨ ob`. |
| `run_voblint_dead_unreached` | `DEAD res v ⟹ reaching ds p v = {}`. |
| `run_voblint_arithmetic_safe` (facts `_intra`, `_call`, `_return`) | At a `SAFE` point and a reaching store, every obligation of every expression an intra edge or a call argument there evaluates holds, and a returned value converted to a narrower destination kind lies in that kind's range. |
| `run_voblint_arithmetic_refuted` | A diagnostic with verdict `Check_Refuted` fails at every store reaching its point: `¬ s ⊨ diagnostic_obligation d`. |
| `run_voblint_no_signed_overflow`, `run_voblint_no_conversion_overflow` | Corollaries of the previous: at a `SAFE` point, every nested signed `TArith` other than `AMod` computes a result in its kind's range, and every narrowing `TCast` converts a value its target represents. |
| `run_voblint_obligations_cover` | Every such obligation is in `obligations_at ds p v`, so `SAFE` covers it. |
| `run_voblint_source_sound` | For `s0 ∈ init_stores (kenv_of ds)` and `star (pstep (kenv_of ds) (elab_ptable p ds)) (main_body …, s0, []) (residual, s, frs)`: some node `v` simulates the configuration (`elab_ptable p ds, elab_cfg p ds, prog_main_name ⊢ (residual, s, frs) ≈ (v, s, stk)`), `s ∈ reaching ds p v`, a reported state at `v` describes `s`, `¬ DEAD res v`, and every `PROVED`, `REFUTED` and `SAFE` claim at `v` holds of `s`. Existential in `v`. |
| `run_voblint_check_sound` | Same premises and a run about to execute `Check l e` (`next_check residual = Some (l, e)`): a listed check with label `l` and expression `e` sits at a node `s` reaches, its verdict is not `Dead`, and a decided verdict holds of `s`. |
| `run_voblint_labelled_check_sound` | When `distinct (map check_label (report_checks res))`, every row labelled `l` is that check. That the parser writes each check's own source position into its label is outside the theorem. |
| `run_voblint_spine` | For any context policy `adm` with root `c₀`, given that every `valid_activation_trace` carries a context and that the buckets `⋃c'. activation_collect … v c'` equal `reaching ds p v`: a source run has a trace `t` and a context `c` with `s ∈ activation_collect … v c`, and the conclusions of `run_voblint_sound` hold at `v`. |
| `run_voblint_call_string_chain` | The spine at `conf_context conf = Call_String k`, with `adm = context_policy_of_fun (cs_context k)` and root `[]`; both premises of the spine are discharged. |
| `run_voblint_entry_state_chain` | The spine at `conf_context conf = Entry_State`, with `adm` the `mcp_es.entry_context_rel` (flow-sensitive program globals) or `mcp_split_es.entry_context_rel` (flow-insensitive) of the configuration and root `mcp_root_ctx`; the premises follow from the solve having terminated. |

None of these says that `v` is reached. `PROVED` and `REFUTED` constrain only
reaching stores; `DEAD` is the reachability claim.

The `run_voblint` rows prove partial correctness. Solver termination is not
proved; an answer exists only where the solve returned. Parsing, the parser's
block-scope resolution and declaration rewriting, diagnostic source positions,
rendering, code generation, the OCaml compiler and the handwritten CLI are
outside the proved chain.

## Configuration coverage

`run_voblint` takes a `voblint_conf`
([`Analysis_Config.thy`](../src/Executable_Surface/CLI/Analysis_Config.thy)):
the activated `analysis` list (`Interval`, `Congruence`, `Ana_Int` at each
`refine_mode`, `Order`, `Sign`, `Parity`), a `context_policy` (`Call_String k`
or `Entry_State`), a `globals_rule`, a `program_globals` placement and a
`sem_conf` whose `sem_int_signed_overflow` is `Assume_Top` (the default) or
`Assume_Wraparound`. Every public theorem above quantifies over all of them.
`report_run` dispatches to `cs_run` or `es_run`, each of which solves the
registration for its placement (`mcp_cs`, `mcp_es`, `mcp_split`,
`mcp_split_es`); `report_run_sound` proves the result sound in each case.
