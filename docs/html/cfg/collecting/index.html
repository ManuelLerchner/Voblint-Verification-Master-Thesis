Goblint Formalization · CFG / Collecting

CFG collecting semantics

Operational collecting specification on the compiled CFG: least fixpoint cfg_collect at every program point, path-based characterisation cfg_edges_collect, and exit projection runs_to with small-step equivalence. Sources live in src/CFG/Collecting/; import CFG_Runs_To_Bridge for the full chain.

Public entry

There is no umbrella CFG_Collecting.thy (removed). Session theories and downstream proofs import Goblint_Formalization.CFG_Runs_To_Bridge, which re-exports the five-theory chain below. Core graph and path infrastructure remain in src/CFG/ — see the CFG core walkthrough.

∎Overview

Given a compiled graph g and initial store set S at entry, collecting semantics answers: which stores can appear at program point v along some valid control-flow path?

Fixpoint view (canonical)

cfg_collect g S v — least fixpoint of monotone transformer cfg_collect_F over environments cenv = pp ⇒ store set. Defined in CFG_Edges_Collect.thy.

Path view (equivalent)

cfg_edges_collect g S v — union of edges_collect es S over all entry-to-v labelled paths es. Defined in CFG_Collecting_Core.thy; equality at every v in CFG_Path_Bridge.thy.

Thesis sentence

Analyzer soundness is stated against cfg_collect at every program point, not only at exit. The equation-system post-fixpoint over-approximates that semantics pointwise; see equations layer (post_fixpoint_sound) (post_fixpoint_sound, pipeline_invariant_sound). Terminating runs correspond to exit membership via runs_to; partial and non-terminating behaviour is covered by the path-based formulation without requiring a final store.

02Per-theory roles

What each file contributes to the proof library.

CFG_Edges_Collect.thy — fixpoint engine

Per-edge transfer on store sets and the collecting fixpoint.

Actionedge_collect a S
EA_NopS
EA_Assign x a{s(x := aval a s) | s ∈ S}
EA_Assume bfilter bval b s
EA_AssumeNot bfilter ¬ bval b s
 
edges_collect es S     -- fold edge_collect along labelled path es

collect_pp g ρ v = ⋃ { edge_collect a (ρ u) | (u,a,v) ∈ edges g }

cfg_collect_F g S ρ v =
  if v = cfg_entry g then S ∪ collect_pp g ρ v
  else collect_pp g ρ v

cfg_collect g S = lfp (cfg_collect_F g S)

Monotonicity lemmas (collect_pp_mono, cfg_collect_F_mono, cfg_collect_lfp_unfold, cfg_collect_mono_S) justify lfp and downstream soundness transfers.

CFG_Collecting_Core.thy — path union before compound splitting

cfg_edges_collect g S v =
  ⋃ { edges_collect es S | es. cfg_path g (cfg_entry g) es v }

One-step extension cfg_edges_collect_step and post-fixpoint cfg_edges_collect_post show the path collector sits above cfg_collect_F. Lemma cfg_collect_le_edges_collect: fixpoint ⊆ path side (first half of the equivalence proof).

CFG_Compound_Paths.thy — bureaucratic path algebra

Large library for paths through compiled Seq, If, While: splitting (cfg_path_Seq_split, cfg_path_If_split, cfg_path_While_loop_peel), offset shifting (edges_collect_offset_path), and compile_Seq_0 / compile_If_0 / compile_While_0 for case splits on to_cfg c.

CFG_Path_Bridge.thy — lfp ↔ paths ↔ small-step (forward)

  • cfg_collect_step, path_sound_cfg_collect — push stores along paths inside the fixpoint.
  • cfg_collect_eq_cfg_edges_collect — at every v, not just exit.
  • compile_path_small_step — path + membership ⇒ (c,s) →* (SKIP,t).

CFG_Runs_To_Bridge.thy — public entry, exit sugar, reverse bridge

File header documents the intended import surface. Defines runs_to and proves small-step biconditional plus command-structure elimination lemmas used when relating paths to IMP execution.

Pipeline invariant (pipeline_invariant_sound): cfg_collect (to_cfg c) {s} v ⊆ γ_state (run_analysis … v) for all v. Constraint-system soundness (post_fixpoint_sound) is proved against this formulation via cfg_collect_F / collect_pp.

CFG_Path_Bridge.thy cfg_collect_eq_cfg_edges_collect 
cfg_collect g S v = cfg_edges_collect g S v

Bridges the fixpoint used in equation soundness to the path union used in small-step and compound-command proofs. Comment in theory notes both sides are needed: pipeline states invariant in lfp form; small-step bridge talks CFG paths.

CFG_Runs_To_Bridge.thy runs_to_def 
runs_to c s t ⟷ t ∈ cfg_collect (to_cfg c) {s} (cfg_exit (to_cfg c))

Definitional abbreviation — not a second operational semantics. Text in theory: exit membership in cfg_collect, packaged for source-level consumers (sign_pipeline_sound, examples).

04Small-step bridge

Link exit collecting to IMP2 small-step termination to SKIP.

THEOREM runs_to_iff_small_step biconditional 
runs_to c s t ⟷ (c, s) →* (SKIP, t)

Combined from runs_to_small_step (forward) and small_step_runs_to (reverse). Forward direction typically chains cfg_collect_eq_cfg_edges_collect with path membership and compile_path_small_step; reverse builds a CFG path from small-step execution (large command-case library in this file).

Proof flow (exit)
  • runs_to → small-step: unfold runs_to_def, rewrite with path equality, extract path from cfg_edges_collect, apply compile_path_small_step.
  • small-step → runs_to: induction on (c,s) →* (SKIP,t); construct cfg_path and show store in edges_collect; lift to cfg_collect at exit.
sequenceDiagram participant SS as small_step participant RT as runs_to participant CC as cfg_collect exit participant CE as cfg_edges_collect exit SS->>RT: small_step_runs_to RT->>CC: runs_to_def CC->>CE: cfg_collect_eq_cfg_edges_collect CE->>SS: compile_path_small_step

Partial / non-terminating programs: soundness at interior points does not require runs_to or reachability of SKIP. The path predicate cfg_path covers any finite prefix of execution visible at some v.

05Downstream

How collecting semantics feeds the analyzer soundness chain.

Equations/Constraint_System_Sound.thy

Imports CFG_Runs_To_Bridge. Main results:

  • post_fixpoint_sound — any abstract post-fixpoint env pointwise over-approximates cfg_collect g S at every v.
  • exit_sound — corollary at cfg_exit; concrete store in γ_state (env exit).
-- strategy (from theory header):
-- 1. post-fixpoint characterization
-- 2. show cfg_collect_F (γ ∘ env) ≤ γ ∘ env  →  lfp ≤ γ ∘ env
-- 3. conclude concrete membership at each v

Pipeline/Pipeline.thy

  • pipeline_invariant_sound — end-to-end: TD solver result ⊇ cfg_collect at every v.
  • sign_pipeline_sound / sign_pipeline_invariant_sound — sign-domain instances.
