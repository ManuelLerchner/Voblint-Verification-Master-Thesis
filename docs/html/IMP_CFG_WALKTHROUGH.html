Goblint Formalization · IMP & CFG

From IMP source to CFG collecting semantics

A focused tour of src/IMP2/ and src/CFG/: what each definition means, how compile translates every command form, and which proved lemmas connect AST-level collect to graph-level cfg_collect at the program exit. This is the semantic foundation for the equation-system and solver soundness chain described in the pipeline walkthrough.

Proof status · IMP & CFG layer

No sorry in src/IMP2/ or src/CFG/. Bridge theorem cfg_collect_exit_eq_collect is fully proved in CFG_Collecting.thy. Optional lemmas that were previously placeholders (collect_While, exit-reachability helpers) were removed rather than left as sorry they are not needed on the critical path. The sign pipeline through equations, solver, and goblint_sign_sound is closed. Interval stretch and optional paths still use sorry see docs/PROOF_PHASES.md.

∎The equivalence we prove

Two views of “what states can appear when the program finishes?” must coincide.

flowchart LR subgraph imp ["IMP2 (AST)"] BS["big_step (c,s) ⇒ t"] COL["collect c S = {t | ∃s∈S. (c,s)⇒t}"] BS --> COL end subgraph cfg ["CFG (graph)"] TC["to_cfg c"] PATH["cfg_path + path_collect"] CC["cfg_collect (to_cfg c) S (exit)"] TC --> PATH --> CC end COL <-->|"cfg_collect_exit_eq_collect"| CC
THEOREM cfg_collect_exit_eq_collect bridge 
cfg_collect (to_cfg c) S (cfg_exit (to_cfg c)) = collect c S

Proved (no sorry in this file or its IMP/CFG dependencies). Once this holds, any sound over-approximation of cfg_collect at the exit node (from the equation system + abstract domain) is automatically sound for collect c S, hence for concrete terminating stores via big_step.

Proof strategy (two directions)
  • CFG ⊆ IMP (cfg_path_collect_exit_le_collect): every store reachable along a CFG path to exit corresponds to some big_step execution. Uses compile_path_big_step.
  • IMP ⊆ CFG (collect_le_cfg_collect_exit): every big_step output is captured by the CFG fixpoint at exit. Uses big_step_cfg_path and path_sound_cfg_collect.

01IMP2 syntax

src/IMP2/IMP2_Syntax.thy self-contained AST (extends classic IMP with richer expressions).

Stores and names

type_synonym vname = string · store = vname ⇒ int

A store maps every variable name to an integer. There is no heap or scope stack: assignment updates one variable, leaving others unchanged (s(x := v) from HOL).

Arithmetic expressions aexp

N int          -- literal
V vname        -- variable read
Plus a1 a2
Minus a1 a2
Times a1 a2

Boolean expressions bexp

Bc bool
Not b | And b1 b2 | Or b1 b2
Less a1 a2     -- a1 < a2
Eq a1 a2       -- a1 = a2

Commands com

Same control-flow shapes as HOL-IMP

SKIP
x ::= a                    -- Assign
c1 ;; c2                   -- Seq (sequential composition)
IF b THEN c1 ELSE c2
WHILE b DO c

Countability and a linear order on datatypes are instantiated here so finite predecessor sets in the CFG layer can be sorted for Finite_Set.fold.

02Big-step operational semantics

src/IMP2/IMP2_Semantics.thy evaluation of expressions and commands.

aval / bval

fun aval :: aexp ⇒ store ⇒ int · fun bval :: bexp ⇒ store ⇒ bool

Standard structural recursion: literals, variable lookup, arithmetic operators; booleans with short-circuit-free And/Or (both operands always evaluated).

big_step

inductive (c,s) ⇒ t infix matches HOL-IMP.Big_Step

RuleMeaning
SkipSKIP leaves the store unchanged.
AssignUpdate x to aval a s.
SeqRun c1 then c2 on the intermediate store.
IfTrue / IfFalseBranch on bval b s.
WhileFalseLoop exits when guard is false.
WhileTrueOne body iteration, then recurse on the loop.

Proved lemmas (why they matter)

  • skip_simp, assign_simp characterise single-command executions; used in inversion proofs.
  • big_step_If_iff collect_If splits on the guard without duplicating case analysis.
  • big_step_determ at most one final store per (c,s); concrete runs are unique when they exist.
  • sim_* family command similarity (c ~ c'); auxiliary material for program transformations (not on the main equivalence path).

03Collecting semantics on the AST

src/IMP2/IMP2_Collecting.thy lift big-step to sets of stores.

collect

definition collect :: com ⇒ store set ⇒ store set

collect c S = { t. ∃s∈S. (c, s) ⇒ t }

Interpretation: from any initial store in S, run c; collect all possible final stores. Non-termination contributes nothing (no ⇒ conclusion). This is the operational “may” semantics at the command exit.

Compositional lemmas (proved)

  • collect_SKIP collect SKIP S = S.
  • collect_Assign image of assignment over S.
  • collect_Seq collect (c1;;c2) S = collect c2 (collect c1 S); sequential composition as function composition on sets.
  • collect_If partition S by bval b, union the two branches.
  • collect_mono larger input ⇒ larger output; needed for fixpoint reasoning on loops and for abstract soundness.
  • while_collect_mono the loop body’s one-step transformer is monotone; prerequisite for lfp characterisations.

While-loops in the bridge proof use induction on big_step (big_step_cfg_path), not a separate collect_While lemma (removed from the codebase).

Running example
c = x ::= N 1 ;; WHILE Less (N 0) (V x) DO x ::= Plus (V x) (N (-1))
s = (λ_. 0)   -- all variables 0

collect c {s} is the singleton {t} with t x = 0. Every sound analysis must over-approximate this set at program exit.

04CFG model

src/CFG/CFG_Def.thy programs as finite labelled graphs.

Program points and edge actions

type_synonym pp = nat

datatype edge_action =
  EA_Nop
| EA_Assign vname aexp
| EA_Assume bexp      -- keep states where bval b s
| EA_AssumeNot bexp   -- keep states where ¬ bval b s

Edges carry the effect taken when traversing them. Branching in IF/WHILE becomes assumption edges (filtering stores), not a separate control-flow datatype.

CFG record

record cfg =
  cfg_entry :: pp
  cfg_exit  :: pp
  cfg_edges :: (pp × edge_action × pp) set

Derived notions

DefinitionRole
cfg_nodesEntry, exit, and all endpoints appearing on edges.
predecessors g vIncoming edges to v; used in equation-system rhs joins.
successors g uOutgoing edges from u.
cfg_wf gEntry ≠ exit, finite edges, endpoints in cfg_nodes.
offset_edges / cfg_offsetShift all program points by k; used when composing sub-CFGs at offset n > 0.

Proved lemmas

  • finite_predecessors from finite cfg_edges; enables Finite_Set.fold in the solver layer.
  • offset_edges_* algebraic laws for shifting edge sets when gluing compiled fragments.
  • cfg_edge_endpoints_in_cfg_nodes well-formedness helper for to_cfg_wf.

05Compilation: IMP → CFG

src/CFG/IMP2_to_CFG.thy structured translation with a fresh program-point counter.

compile c n

returns (n', entry, exit, edges)

  • n first free program-point id (all allocated ids lie in [n, n')).
  • entry, exit unique entry/exit of command c's subgraph.
  • edges labelled edges for this command only (glue edges added at composition sites).

to_cfg c wraps compile c 0 into a cfg record with global entry/exit and edge set.

Per-construct compilation (with examples)

Below, compile … 0 is shown. Node ids are naturals; each command allocates a fresh interval [n, n').

SKIP

  (2, 0, 1, {(0, EA_Nop, 1)})

c1 ;; c2

Compile c1 at n, then c2 at the returned counter n1. Connect c1's exit to c2's entry with EA_Nop.

flowchart LR e1["c1 entry"] --> x1["c1 body"] --> ex1["c1 exit"] ex1 -- EA_Nop --> e2["c2 entry"] --> x2["c2 body"] --> ex2["c2 exit"]

Example: (x ::= N 1) ;; (y ::= V x) uses nodes 0–1 for the assign, 2–3 for the second, plus edge (1, EA_Nop, 2).

IF b THEN c1 ELSE c2

Entry splits on EA_Assume b and EA_AssumeNot b. Each branch compiles independently; both branch exits join the shared exit via EA_Nop.

flowchart TD en(("entry")) en -- "Assume b" --> b1["c1 subgraph"] en -- "AssumeNot b" --> b2["c2 subgraph"] b1 -- EA_Nop --> xn(("shared exit")) b2 -- EA_Nop --> xn
WHILE b DO c

Loop head = entry. Guard true → body; body exit returns to head with EA_Nop. Guard false → exit.

flowchart TD head(("head = entry")) head -- "Assume b" --> body["body subgraph"] body -- EA_Nop --> head head -- "AssumeNot b" --> exit(("exit"))

This is the CFG our running example uses after the initial assignment: nodes 2–5 form the loop; node 5 is cfg_exit.

Compilation infrastructure lemmas (proved)

  • compile_fresh allocated nodes stay ≥ counter; disjoint subgraphs when composing.
  • compile_ge counter monotone; supports induction on command size.
  • compile_entry_ne_exit every command has distinct entry/exit (needed for cfg_wf).
  • compile_finite → to_cfg_finite finite edge set for folds and fixpoints.
  • to_cfg_wf compiled graphs are well-formed.
  • compile_add_offset, compile_from_0_offsets shifting lemmas for nested compilation at n > 0 (Seq/If/While proofs in CFG_Collecting).
  • to_cfg_compile exposes the quadruple behind to_cfg c for case splits.

06CFG paths

src/CFG/CFG_Path.thy labelled paths, not just reachability on nodes.

cfg_path g u es v

Inductive predicate: from u to v following edges in g, recording each step as (edge_action, next_pp) in list es. Empty list = stay at u; cons = take one edge then continue.

Abbreviation g ⊢ u →* v (cfg_reaches) existence of some path list.

Why labelled paths?

The equation-system soundness proof must compose transfer functions along the same actions the concrete collector uses. Recording edge_action on each step lets us relate path_collect to sequences of edge_collect steps without guessing actions from node names alone.

Proved lemmas (selected)

  • cfg_path_append concatenate paths; used everywhere in Seq/If/While splitting.
  • cfg_path_cases / cfg_path_induct disciplined inversion and induction (FormalSSA-style library).
  • offset_path, cfg_path_offset paths commute with shifting pp ids; sub-CFG paths lift to compound graphs.
  • cfg_path_split_last peel last step; used in While loop reasoning.
  • cfg_entry_reachable entry is reachable; used in path-soundness proofs.

Former placeholders cfg_exit_reachable_from_entry and to_cfg_exit_reachable were removed from CFG_Path.thy (not needed for the bridge; general exit reachability is false for arbitrary cfg_wf graphs).

07CFG collecting semantics

src/CFG/CFG_Collecting.thy fixpoint over program points, plus path-based characterisation.

Edge and path collectors

edge_collect a S

ActionEffect on set S
EA_NopS unchanged
EA_Assign x a{s(x := aval a s) | s ∈ S} mirrors collect_Assign
EA_Assume bfilter bval b s
EA_AssumeNot bfilter ¬ bval b s

path_collect es S

fold edge_collect along es; pp components in steps are ignored

path_collect_offset_path proves shifting node labels does not change collected stores the formal justification that offset compilation is invisible to semantics.

Fixpoint formulation

collect_pp g ρ v = ⋃ { edge_collect a (ρ u) | (u,a,v) ∈ cfg_edges g }

cfg_collect_F g S ρ v =
  if v = cfg_entry g then S ∪ collect_pp g ρ v
  else collect_pp g ρ v

cfg_collect g S = lfp (cfg_collect_F g S)     -- cenv = pp ⇒ store set

Intuition: start with initial stores S at entry; repeatedly push stores forward across edges and join at merge points until stable. This is the CFG analogue of dataflow analysis without abstraction.

cfg_path_collect g S v

⋃ { path_collect es S
  | es. cfg_path g (cfg_entry g) es v }

Union over all entry-to-v paths often easier for one-step inclusion proofs than unfolding lfp.

Monotonicity & fixpoint lemmas (proved)

  • edge_collect_mono, path_collect_mono(_strong) needed for lfp existence and soundness transfers.
  • collect_pp_mono, cfg_collect_F_mono transformer monotone in environment ρ.
  • cfg_collect_lfp_unfold cfg_collect = cfg_collect_F (cfg_collect).
  • cfg_path_collect_step, cfg_path_collect_post path collector is a post-fixpoint of cfg_collect_F.
  • cfg_collect_le_path_collect fixpoint below path union; links cfg_collect to paths.
  • cfg_collect_step, path_sound_cfg_collect push states along one path inside the fixpoint.

Compound-command path lemmas (proved)

Large library splitting paths through compiled Seq, If, While into sub-command paths (often at offset 0 inside the sub-graph). Examples:

  • cfg_path_Seq_split, cfg_path_If_split, cfg_path_While_loop_peel
  • compile_Seq_0, compile_If_0, compile_While_0 shape of compile at counter 0.

These are the bureaucratic heart of big_step_cfg_path: each big-step rule must construct a concrete path through the corresponding CFG pattern.

08Equivalence bridge lemma by lemma

How the main theorem is assembled, and what each milestone contributes.

flowchart TD subgraph dir1 ["CFG ⊆ IMP (exit)"] A1["cfg_path at exit"] --> A2["path_collect"] A2 --> A3["compile_path_big_step"] A3 --> A4["∈ collect c S"] end subgraph dir2 ["IMP ⊆ CFG (exit)"] B1["(c,s) ⇒ t"] --> B2["big_step_cfg_path"] B2 --> B3["path_sound_cfg_collect"] B3 --> B4["∈ cfg_collect exit"] end A4 --> EQ["cfg_collect_exit_eq_collect"] B4 --> EQ
L-bridgecfg_collect_exit_eq_collect
cfg_collect (to_cfg c) S (cfg_exit (to_cfg c)) = collect c S

Proved by antisymmetry from the two lemmas below.

L-⊆impcfg_path_collect_exit_le_collect
cfg_path_collect (to_cfg c) S (cfg_exit (to_cfg c)) ⊆ collect c S

Any store obtained by following a CFG path to exit and applying path_collect comes from some big_step run. Delegates to compile_path_big_step: paths in the compiled graph simulate IMP execution.

L-compile-pathcompile_path_big_step
cfg_path (to_cfg c) entry es exit ∧ t ∈ path_collect es {s}
  ⟹ (c, s) ⇒ t

Induction on cfg_path; each edge action matches a small-step of concrete evaluation. Assignment/assume cases align edge_collect with aval/bval.

L-⊇cfgcollect_le_cfg_collect_exit
collect c S ⊆ cfg_collect (to_cfg c) S (cfg_exit (to_cfg c))

From t ∈ collect c S obtain (c,s) ⇒ t, then big_step_cfg_path builds exit-path es with t ∈ path_collect es {s}, then path_sound_cfg_collect pushes into the fixpoint.

L-big-pathbig_step_cfg_path
(c, s) ⇒ t ⟹ ∃es. cfg_path (to_cfg c) entry es exit ∧ t ∈ path_collect es {s}

Induction on big_step; largest proof in the file. Each rule matches the compilation scheme (Skip/Assign singleton edge, Seq glue, If branches, While loop unfold).

L-path-soundpath_sound_cfg_collect
cfg_path g entry es v ⟹ path_collect es S ⊆ cfg_collect g S v

Induction on path; one step uses cfg_collect_step (fixpoint pushes across an edge). Entry stores seeded by cfg_collect_F at entry.

L-reachcfg_reach_entry
S ⊆ cfg_reach (to_cfg c) S (cfg_entry (to_cfg c))

Initial stores appear at entry in the collecting environment; used in downstream soundness proofs (not in the equality theorem itself).

After this theorem

The equation system in src/Equations/ talks about cfg_collect (and its abstract version). post_fixpoint_sound is proved in Constraint_System_Sound.thy; composed with the TD solver and cfg_collect_exit_eq_collect, this yields goblint_sign_sound for the sign domain.
