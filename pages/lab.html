Compiler and semantics

Source → graph morph

Watch the compiler take a program apart

The compiler reads a procedure one statement at a time and turns each statement into a numbered node with outgoing edges. Its target is already known before that statement is compiled: every statement is compiled against the number of the statement after it. This figure replays that walk on the counting loop, with the node numbers and edge labels the real compiler produces. It would sit in "What a run is", before the step-through, where the page currently takes the graph as given.

Particles and regions

Many runs in, one region per node out

Every dot is one run of the program, dropped at the value of x it has at each node it reaches. Switch to the abstract view and the dots give way to the one interval the analysis keeps per node. No interval leaves a dot out, which is soundness. But the runs only ever reach multiples of three, and an interval cannot say so: every band also covers integers no run has. On the left that makes a node look reachable that no run reaches; on the right the guard rules everything out, and the analysis marks the check DEAD. This would sit after the collecting-semantics rungs of "The proof chain", or replace the opening testing-versus-abstraction figure.

Solver and recursion

Recursion as a spiral

A call that never stops calling

f(x) calls f(x + 1) forever, so real runs wind outward on an endless spiral: f(0), f(1), f(2), each turn wider than the last. The analysis has to describe every turn with finitely many contexts. Whether it can depends on the settings: Join and entry-state contexts follow the spiral and never finish, warrowing cuts across it. Switch to the same function stopped at x = 10 and every setting finishes. It belongs next to the “Growing recursion” row of “Which Globals setting should you pick?”, or to the price of precision.

Architecture

Geological strata

The formalization in cross-section

Every Isabelle session is a rock layer lying just above the highest session it builds on, from the logic at the bottom to the examples at the surface. Hover a session and the layers it rests on light up. A layer's thickness grows with its line count, so the drill core also shows where the weight sits: the vendored solver, the examples, the framework. It would fit beside the iceberg in “Why this takes so long to prove”, which counts volume but not structure.
