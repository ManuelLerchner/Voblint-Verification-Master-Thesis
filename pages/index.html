A verified Goblint-style static analysis pipeline in Isabelle/HOL. Voblint connects verified CFG compilation, activation-local operational semantics, executable equation generation, and a verified top-down solver to a source-level soundness statement about the analyzer's own output.

End-to-end soundness

What Voblint proves

The proof follows the same pipeline that the executable analyzer uses: from source execution, through CFG states and generated equations, to the post-solution and final check report. 

Execution:  VIMP AST -> CFG -> equation system -> verified TD solver
                     -> computed post-solution -> check report

Proof:      source execution -> activation-local traces (valid_ltr)
                             -> per-point collection (ltr_collect)
                             -> included in the concretization of that result

The headline theorem, run_voblint_certified_source_sound, ranges over the same run_voblint entry point exported to OCaml and over each domain, globals rule, and context policy. For a modeled source execution, it supplies a matching CFG node and call stack with the following guarantees.

csim … (v, s, stk)
The compiler's forward simulation relates the source state to CFG node v.
s ∈ ltr_collect … v
A valid activation-local trace genuinely reaches v with store s.
analysis_result_covers … v s
The abstract state reported for v, under an admitted context, contains s.
checks_sound_at out v s
No live row at v is mislabeled: every PROVED or REFUTED verdict is correct for s.
Every report returned for a terminating accepted solve over-approximates all modeled source executions.

Boundary. Termination remains a per-program logical premise. The proof does not cover lexing, parsing, code generation, the OCaml toolchain, rendered strings, GraphViz, or analysis precision.

Reading a result

The graph, and the state behind it

Full abstract product states do not fit cleanly inside CFG nodes. --html therefore keeps the graph sparse and places each node's detailed state in the report, where source lines, contexts, checks, and diagnostics can be inspected together.
