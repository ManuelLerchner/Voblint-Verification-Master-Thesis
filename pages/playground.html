Entry seeds

A call cannot write its callee's entry state directly: the solver side-effects only global unknowns. So each call publishes the entered state into a seed, one per procedure entry per context, and the callee's entry reads it back. Calls routed to the same context meet in its seed, merged by the Globals rule. Shown here are the callee's formals and the program's globals; the other locals are reset on entry. These analyses keep declared globals in the per-point state, so the solver's analysis-wide global slot stays unused. Presentation only; no soundness statement reads these rows.

    Every domain, globals rule, and context combination runs exactly as selected: the solver warrows locals at loop heads under every rule, and the rule only decides how side-effected globals are merged.
