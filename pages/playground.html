VIMP is a small IMP-style language with __voblint_check(cond) assertions. The analysis runs locally through the Isabelle-generated core; your source is not uploaded. Parsing, rendering and this page sit outside the verified component. How it works explains every setting and every mark below.

Solver trace

Every solver step of the run, as voblint --trace --verbose prints it, recorded by the run itself: each unknown solved, each query with the value it returns, each side effect, each update, each destabilization and each call's routing, in a Goblint-aligned tracing vocabulary, indented by the solver's query depth. A banner marks where the solver asks for a procedure's result.

Three layers: the solver result is the exported computation of proved equations, and the trace calls come from code equations proved equal to the untraced ones. The trace is an unverified observation of that computation, recorded by a hook that returns nothing, swallows exceptions and never touches solver state. The solve replay further down is an unverified visualization of the trace.

Steps through the solve on the control-flow graph, one solver step at a time. The solver starts from the program's exit and queries backward toward the entry. Each node shows the value the solver holds for its point in its context box at that step; every context has its own box, so every unknown has its own node. The global unknowns are the seeds: the circle at the top of each box, which the calls routed to that context publish into and its entry reads.
